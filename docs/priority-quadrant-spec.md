# 桌面端「象限」视图设计

> 状态：设计稿（2026-09-04），尚未实现。本文只定义布局、交互与写入路径，不含代码。
> 前置约定：`docs/desktop-mvp-spec.md`（视觉方向、卡片、拖放意图模型）、`docs/format-spec-v1.md` §3（`!1`–`!4` 优先级 token）。

## 0. 一句话

「象限」是「目标」之外的第四个一级视图：把所有未完成的 Project Task 按文件里的 `!` 优先级分到 2×2 四格，没有 `!` 的任务留在网格下方的「未定级」托盘；把卡片拖进某一格，就把这一档优先级写回 `TODO.md`。

这个视图的工作是**定级**，不是又一个看板：列、勾选状态、排序键 `^` 一律不动，它只读写任务行上的 `!` token。

## 1. 用户与场景

- 用户是与 agent 协作的开发者，通常在一次会话开始前、或 agent 批量新增了一批任务之后打开这个视图，用 30 秒回答「哪些是 !1，哪些先放着」。
- 输入状态：一批任务刚从命令栏或 CLI 进来，没有优先级；或者优先级已过时，需要整体重排。
- 成功标志：托盘清空、`!1` 格子里只剩真正要先做的事、每次拖动都对应文件里一行的一个 token 变化。

访客模式：Operate。可扫读、可键盘操作、与「目标」页共享同一套卡片与拖放语言，优先于表现力。

## 2. 信息架构

### 2.1 导航

左侧「工作视图」新增第四项：

| 序号 | 标签 | 图标 | 徽标计数 |
|---|---|---|---|
| 04 | 象限 | 2×2 网格（`Icon` 新增 `grid`） | 未定级任务数（为 0 时不显示） |

徽标数的含义与「目标」的推进中计数、「随记」的 Capture 计数一致：都是「等着人做决定的数量」。

### 2.2 页头

沿用 `view-heading` 结构：

- 标题 `优先级象限`；元信息 `N 项未完成 · M 项未定级`，只读模式追加 `只读浏览`。
- 右侧复用「目标」页的截止日期筛选组（全部 / 逾期 / 今天 / 7 天内），语义与 `desktop-mvp-spec.md` §4 完全相同，作用于四格与托盘的全部任务。计数为 0 的筛选禁用。

已完成任务不出现在本视图。页头不放「已完成」入口；用户回「目标」页看已完成栏。

## 3. 数据到格子的映射

| 区域 | 命中条件 | 落入时写入 |
|---|---|---|
| 格 1 `!1 最高` | `priority == 1` | 把行上的 `!` token 改为 `!1`（没有则追加） |
| 格 2 `!2 高` | `priority == 2` | 同上，`!2` |
| 格 3 `!3 中` | `priority == 3` | 同上，`!3` |
| 格 4 `!4 低` | `priority == 4` | 同上，`!4` |
| 托盘 `未定级` | 没有 `!` token | 删除行上的 `!` token |

- 参与范围：`completed == false` 且不在 `type: done` 列的任务，含游离任务（`column == null`）。与「目标」页「推进中 + 待办」的集合一致。
- 子任务按快照的扁平顺序展示，与「目标」页一致；卡片不额外表达层级。
- 四格严格对应四个 `!` 档位，托盘对应「没有 `!`」。**不把 `!4` 与「无优先级」合并**：两者在文件里是两个事实，合并后无法从界面重建文件。
- 桌面端当前把 `!4` 当作无优先级（`TaskPriority = 1 | 2 | 3 | null`），Rust 端已透传 `Option<u8>`。实现时需把前端类型放宽到 `1 | 2 | 3 | 4 | null`，否则 `!4` 会被误入托盘、拖动一次就丢 token。

### 3.1 格内顺序

格内顺序是派生的，不写文件，也不能通过拖动调整。规则依次为：

1. 推进中列（`splitColumns().focus`）的任务在前；
2. 其次按截止日期：逾期 → 今天 → 7 天内 → 更远 → 无截止；
3. 最后按文件顺序（列顺序 → 列内 `^` 排序键）。

这样每一格的第一张卡片都是「这一档里此刻最该动的」，且规则可以向用户解释。

## 4. 布局

```
┌ view-heading ──────────────────────────────────────────────────────────┐
│ 优先级象限              12 项未完成 · 0 项未定级     [全部 12][逾期 0][今天 0][7 天内 0] │
├────────────────────────────────┬───────────────────────────────────────┤
│ !1 最高                    4  │ !2 高                              7  │
│ ────────────────────────────── │ ───────────────────────────────────── │
│ ▌推进中                        │  ┌ 卡片 ┐                             │
│ ┌ 卡片 ┐                       │  ┌ 卡片 ┐                             │
│ ┌ 卡片 ┐                       │  ┌ 卡片 ┐    （格内独立滚动）           │
│ ┌ 卡片 ┐                       │  ┌ 卡片 ┐                             │
├────────────────────────────────┼───────────────────────────────────────┤
│ !3 中                      2  │ !4 低                              0  │
│ ────────────────────────────── │ ───────────────────────────────────── │
│ ┌ 卡片 ┐                       │   ╭ 虚线 ╮                            │
│ ┌ 卡片 ┐                       │   │ 拖到这里标为 !4 │                  │
│                                │   ╰──────╯                            │
├────────────────────────────────┴───────────────────────────────────────┤
│ 未定级 0 · 所有未完成任务都已定级                       （空时收成一行）  │
└────────────────────────────────────────────────────────────────────────┘
```

- 网格填满工作区高度，与 `goal-layout` 同样的外边界；四格等宽等高，Z 字阅读顺序：左上 `!1`，右上 `!2`，左下 `!3`，右下 `!4`。不按数量或重要度放大某一格，扫读靠位置固定。
- 格与格之间是一条 1px 墨色分隔线交成的十字，不留空隙、不加卡片式圆角；十字交点处不放任何控件。这是「编辑台」的绘图桌感，不是四张浮起的面板。
- 每格页眉：左侧等宽字体 `!1` + 中文档位名 `最高`，右侧计数；页眉下方一条 2px 顶线沿用优先级徽标色（`!1` 朱红、`!2` 琥珀、`!3` 墨灰、`!4` 纸深色）。格子背景保持纸色，不整格上色。
- 格内是纵向卡片列表，独立滚动；滚动时页眉吸顶。
- 托盘横贯底部，卡片横向换行排列。空时收成一行文字，仍是拖放目标；拖动开始时显示虚线边框与「拖到这里清除优先级」。有任务时高度随内容增长，上限约为工作区高度的 30%，超出后托盘内部滚动。
- 托盘不可手动收起：它是这个视图存在的理由，藏起来等于隐藏待办决策。

## 5. 卡片

复用 `TaskCard`，新增 `variant: 'quadrant'`，与 `card` 变体的差异只有三点：

1. 不显示 `P1/P2/P3` 优先级徽标——所在格已经说明了档位；托盘里的卡片同理没有徽标。
2. 推进中列的任务在卡片左缘加一条钴蓝竖线并标注 `推进中`，让「正在做」在四格里一眼可辨。
3. 游离任务标注 `未归列`，与「目标」页一致。

其余保持：正文、截止日期（逾期朱红）、标签、`◐` 进度、`⚠` 失败日期、`↳` 说明、短 ID、拖动把手与菜单按钮。部分完成与失败仍在卡片内一行写完，不弹对话框。

## 6. 交互

### 6.1 拖动改档

- 把卡片拖到另一格或托盘 = 发送 `set_priority` 意图。落点是同一格时不发请求，播报 `「…」仍是 !2`。
- 与 `desktop-mvp-spec.md` §3 相同的意图模型：Rust 写入成功并返回新快照后卡片才落位；失败或冲突时卡片留在原格，横幅提示「文件已在外部更新，请重试」。
- 没有子任务时，拖动只改被拖那一行的 `!` token，不弹确认框。
- 有子任务时，卡片松手后打开轻量确认框，让用户选择：
  - `仅修改这一项`（默认，按 `Enter`）：只修改父任务；
  - `同时修改 N 个子任务`：父任务与全部后代统一改为目标档位，覆盖后代已有的 `!`；
  - `Esc`：取消，父任务与子任务全部留在原位。
- 拖到「未定级」时使用相同确认：选择批量修改会清除父任务及全部后代的 `!` token。
- 确认框出现前不写文件；选择批量修改后，父任务和全部后代必须在一次 Rust 原子写入中完成，任意一行校验失败则整体不写入。
- 格内拖动不改顺序（见 §3.1），落点在同格内视为无操作。

### 6.2 右键菜单与键盘

`TaskContextMenu` 新增「优先级 ›」子菜单，四个视图里都可用（不只在象限页）：

| 菜单项 | 快捷键（卡片聚焦时） | 写入 |
|---|---|---|
| `!1 最高` | `1` | `!1` |
| `!2 高` | `2` | `!2` |
| `!3 中` | `3` | `!3` |
| `!4 低` | `4` | `!4` |
| `清除优先级` | `0` | 删除 `!` |

当前档位在子菜单里打勾并禁用。快捷键只在卡片本身获得焦点、且没有打开行内编辑时生效，避免与进度输入框里的数字冲突。

焦点导航：`Tab` 在四格与托盘之间移动，方向键在格内卡片之间移动，`Shift+F10` / Menu 键打开菜单，`Esc` 关闭。触屏使用卡片上的菜单按钮完成同样操作。

### 6.3 播报

`aria-live="polite"` 播报沿用「目标」页格式：

- 开始：`正在把「…」标为 !1 最高`
- 成功：`「…」已标为 !1 最高` / `「…」已清除优先级`
- 失败：`「…」没有改动，仍是 !2 高`

## 7. 状态

| 状态 | 表现 |
|---|---|
| 项目没有任务 | 与「目标」页相同的空状态：`TODO.md 已连接 / 还没有 Project Task`。 |
| 有任务但全部已完成 | 四格与托盘都空；页头元信息 `0 项未完成`，网格中央一行 `未完成的工作都清空了，已完成在「目标」页`。 |
| 某格为空 | 格内虚线区块 `拖到这里标为 !3`；筛选生效时改为 `当前筛选下没有任务`。 |
| 托盘为空 | 收成一行 `未定级 0 · 所有未完成任务都已定级`；拖动时展开为虚线落点。 |
| 全部未定级（刚 `--adopt` 接管的清单） | 四格全空、托盘占满 30% 上限并滚动；页头徽标显示托盘数。不弹引导。 |
| 只读（`todo serve --read-only`、解析失败、冲突标记） | 拖动把手隐藏、菜单项禁用、快捷键失效；四格照常展示。 |
| 写入中 | 被拖卡片沿用现有 `busy` 态；同一任务的第二次拖动在写入返回前被忽略。 |
| 外部编辑 | 新快照到达后重新分格；正在拖动的卡片若已不在快照中，取消本次拖动并播报。 |

数据范围参考：本仓库自身 `TODO.md` 12 项未完成，分布 `!1`×4、`!2`×7、`!3`×2、`!4`×0、未定级 0。设计按单格 0–50 张、托盘 0–200 张、总量 200 项（产品建议的活跃上限）考虑。

## 8. 响应式

- ≥ 1000px：2×2 网格 + 底部托盘，如 §4。
- 720–1000px：仍是 2×2，卡片切换到更窄的排版（标签折到第二行），托盘卡片单列。
- < 720px：四格纵向堆叠成 `!1 → !2 → !3 → !4 → 未定级` 的单列，每段页眉吸顶；拖动关闭，改档只走菜单与快捷键。

## 9. 动效

只保留两处，均为状态变化：

- 卡片跨格落位：与「目标」页跨列移动相同的位移过渡。
- 拖动进行中：目标格页眉顶线加粗、托盘展开虚线。

首次进入不做分段显现以外的动画；四格内容不浮动、不弹跳。

## 10. 写入路径与实现后果

1. **新 mutation** `{ type: 'set_priority'; id: string; priority: 1 | 2 | 3 | 4 | null }`。Rust 端只替换或删除该行的 `Priority` token，其余字节不动；遵守 `format-spec-v1.md` §4 的区间外科手术与写后校验。建立还原点。
2. **CLI 对等命令** `todo priority <id> <1-4|--clear>`，与桌面端共用同一写入函数，让 agent 也能定级。
3. 前端 `TaskPriority` 放宽为 `1 | 2 | 3 | 4 | null`；`style.css` 新增 `.priority--4`；`TaskCard` 新增 `quadrant` 变体；`Icon` 新增 `grid`；`Sidebar` 的 `MainView` 新增 `'quadrant'`。
4. `TaskContextMenu` 的「优先级 ›」子菜单与快捷键在「目标」页同步可用，不是象限页专属。
5. 新增父任务批量确认参数或独立 mutation，使「同时修改 N 个子任务」能在一次 Rust 原子写入中覆盖整个子树；不能由前端逐项循环调用 `set_priority`。
6. 无需新的 localStorage 状态：视图没有可收起区域，筛选与「目标」页一样只在会话内保留。
7. Playwright：新增 `quadrant.spec.ts` 覆盖单项改档、父任务两种选择、托盘清除、只读禁用、`!4` 不丢失、冲突回退；`mobile.spec.ts` 补单列堆叠。

## 11. 不做

- 不新增文件 token，不发明「重要 / 紧急」轴，不用截止日期推断优先级。
- 不做格内手动排序，不写 `^`。
- 不整格上色，不按数量放大格子。
- 不做自动定级建议（含语义对账）。
- 不跨仓库聚合。

## 12. 决策记录

已拍板（2026-09-04）：

1. 档位中文名：`最高 / 高 / 中 / 低`。CLI 帮助文本与格式规范只说「1 最高」，实现时把这套名字同步到 `todo priority` 的帮助文本。
2. 导航标签：`象限`。
3. 导航徽标计数：未定级数。
4. 父任务有子任务时，让用户在每次操作中选择 `仅修改这一项` 或 `同时修改 N 个子任务`；默认只改单项。拖到「未定级」时执行相同选择。批量修改覆盖全部后代已有的 `!`，并通过一次 Rust 原子写入完成。

# 桌面端「象限」视图规格

> 规则于 2026-09-06 原生人工验收后调整：父子任务始终成组展示和拖动，整组统一改档；窄桌面窗口也支持拖动。本文取代 2026-09-04 设计稿中的平铺子任务、每次选择修改范围和窄窗口禁用拖动规则。
> 前置约定：`CONTEXT.md`、`docs/desktop-mvp-spec.md`、`docs/format-spec-v1.md`。

## 1. 用途与边界

象限用于给 Project Task 定级，不是第二套看板。四格对应 `!1` 最高、`!2` 高、`!3` 中、`!4` 低；无优先级的任务组进入「未定级」托盘。不得把 `!4` 和无优先级合并。

改档只修改任务行的 `!` token，不改变列、checkbox、缩进、父子关系、排序键、正文、说明或 Git 物证。Markdown 仍是事实源，界面必须使用写入后返回的真实快照。

## 2. 父子组

- 以文件顺序、缩进和列边界恢复任务树。每个顶层任务及其后代构成一组；跨列不能误认成同一子树。
- 整组按父任务的优先级归格。子任务及孙任务嵌套显示，不再作为其他格子里的独立卡片。
- 子任务可以显示原有优先级、完成状态、截止日期、标签、进度、失败日期和说明；不能从组内单独拖出，也不提供独立改档入口。
- 只有父卡参与拖动、上下文菜单与优先级数字快捷键。子任务的完成按钮仍可操作，不冒泡触发父卡快捷键。
- 当父任务已完成但仍有未完成后代时，保留父任务作为组上下文；整组已完成则不显示在象限中。
- 打开视图、切换筛选不写文件。旧文件中父子优先级不同，只提示「组内原优先级不同」；必须等到用户实际改档，才统一写入。

「只修改这一项」在之前的设计中仅表示只改优先级，**从未表示解除父子关系**。新的象限整组交互不再显示这个选择；其他视图的单项编辑能力及后端显式 scope 接口不因此删除。

## 3. 整组改档

拖动父卡到另一格、拖到未定级、父卡菜单改档与数字快捷键，统一发送一次：

```ts
{ type: 'set_priority', id: parentId, priority, scope: 'subtree' }
```

- 父任务与所有后代通过一次 Rust 原子写入统一优先级；清除时整组删除 `!` token。
- 不逐条调用子任务 mutation；任意一行校验失败，整体不得写入。
- 没有子任务时，整组操作等同于改单项。
- 拖到当前格且全组优先级已经一致时无操作，不做格内排序。
- 旧文件的组内优先级不一致时，允许在菜单选择父任务的当前档位，以显式统一整组。
- 写入未完成时禁止再次拖动该组；失败显示错误，不保留虚假成功状态。
- 开始、成功、失败通过 `aria-live` 播报，并明确操作对象是整组。

## 4. 计数、筛选与顺序

- 每格右上角显示组数；页头分别显示任务组数、未完成任务数和未定级组数。
- 导航徽标和未定级托盘按父任务是否未定级计数组，不把组内无优先级子任务重复计入托盘。
- 日期筛选命中父任务或任一后代时，保留整组及其上下文，不能筛出一个孤立子任务。
- 组间顺序沿用推进中优先、截止日期其次、文件顺序稳定兜底；组内始终按文件层级和顺序显示。

## 5. 布局与响应式

保留现有暖纸色编辑台、四格十字分区及本地字体，不借本次功能调整替换视觉体系。

- 宽窗口：2×2 等宽四格，父卡内用轻量缩进列表表达后代，不堆叠多个独立任务卡边框。
- 窄窗口：四格变为纵向单列。桌面鼠标拖动保留，靠近可滚动区域边缘时可自动滚动，菜单和键盘仍是等价入口。
- 子任务行显式 `draggable=false`，避免误以为可以独立拆出；父卡显式启用 HTML 拖动，不以窗口宽度关闭。
- 窄窗口上下文菜单采用一个可滚动的底部面板。优先级和「移动到」子菜单在面板内排布，不再各自固定到同一屏幕位置。
- 两个子菜单互斥；窄窗口不使用悬停展开，避免面板重排后触发另一个菜单。
- 从菜单进入确认弹窗前先卸载菜单，再转移焦点；Esc／Tab 的作用域必须可预测，不出现菜单与弹窗抢焦点。

## 6. 原生拖放与快照一致性

主 Tauri WebView 的 `dragDropEnabled` 必须为 `false`，让 HTML 拖放处理任务卡，而不是交给原生文件拖入处理器。速记窗口配置保持独立。

`DesktopSnapshot.revision` 是文件内容哈希，不是递增时间戳：

- A→B→A 是合法往返，重复哈希不代表过期。
- 纯数字外观的哈希也不能按数字大小比较先后。
- 只对同一项目当前相同哈希去重，不维护「永远过期的哈希」集合。
- watcher 事件用于触发重新读取当前状态，不能把迟到的事件载荷直接盖到新状态上。
- 异步读取通过请求编号和写入阶段边界拒绝迟到结果与错误；普通任务写入串行，避免响应乱序。

## 7. 验证要求

自动化至少覆盖：

1. 混合优先级的父子孙在同一组展示，打开与筛选不写入。
2. 父卡拖动、菜单、快捷键只提交一次 subtree 写入，原有缩进和非优先级内容保持不变。
3. 整组在两个档位之间反复往返，文件与界面每一次都一致，最终文件逐字节恢复。
4. 窄桌面窗口单列仍可拖动；菜单互斥、无重叠，按钮在视口内可访问，Esc／Tab 和弹窗交接正常。
5. 原生事件适配的迟到 watcher、旧读取、数字外观哈希与外部内容恢复不会让界面倒退。
6. 真实 Tauri 窗口人工复验拖动反馈、父子组展示和窄窗口菜单；浏览器测试与原生进程启动不能替代这一步。

## 8. 不做

- 不新增文件 token，不发明重要／紧急轴，不用截止日期推断优先级。
- 不做格内排序，不改 `^`，不跨仓库聚合。
- 不自动修改既有文件中不同的父子优先级。
- 不因测试通过就声称未实际观察的原生视觉场景已验收。

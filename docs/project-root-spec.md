# 项目目录与任务来源

## 范围

桌面端选择目录作为 Project Root，HTTP `todo serve` 绑定启动时的当前目录。根目录不必含 `TODO.md`，也不必是 Git 根；找不到任务来源时返回空项目。已有 CLI `list/add/done/priority` 等单文件命令继续操作当前目录的 `TODO.md`。

递归发现文件名为 `TODO.md`、`TODO` 或 `TODO.txt` 的文件（匹配不区分大小写），以及任何以 YAML frontmatter 开头且其中含 `todo-spec` 键的 `.md` / `.markdown` 文件（只读文件头 1 KiB 判定；这让项目可以把 `TODO.md` 留作索引，把明细拆到 `docs/todo/*.md` 并逐个声明加入）；文件来源以相对根目录的 `/` 分隔路径显示。遵守 `.gitignore` 与 `.ignore`，跳过隐藏目录、`node_modules`、`target`、`build`、`dist` 等目录。源码注释 `// TODO` 不属于项目打开时的发现范围；原「扫描与历史」扫描仍是用户另行发起的操作，不自动导入。

发现预算：最多 256 个来源、每源 2 MiB、累计读取 16 MiB、遍历 10,000 个条目。超过预算、读取失败或解析错误会产生来源状态或警告，不把失败来源解释为已清空，也不阻断其他有效来源。

## 来源与任务身份

- `managed`：已具备任务格式声明，可解析且具有写权限的来源允许编辑。
- `unmanaged`：未接管的普通文本或清单，原文只读预览；只提取已有 checkbox，不推测普通段落的任务边界。
- `error`：解析或读取失败，保留来源路径与原因，隔离该文件的编辑操作。

任务的跨文件身份为 `(source_path, local_id)`。文件内原 ID、锚定说明和物证不改名；两个来源中相同 ID 是两个任务。汇总仅是派生视图，不生成中心合并文件。不同来源的列也不因同名而合并。

新增必须明确选择来源，并使用该来源实际的列与完成策略。任务修改、移动和子树定级只作用于一个来源；跨文件移动不作为伪事务提供。旧无来源 mutation 只在项目恰有一个来源且可写时兼容。

## 接管确认

发现文件不会写盘。用户先对一个未接管来源请求差异预览，检查格式声明与缺失稳定 ID 的插入，再确认接管。已有正文、换行和 ID 保留；接管不把普通文本自动拆成任务。批量接管对每个所选来源各生成一份差异，确认后按发现顺序逐个写入，每个写入都锁定该文件预览时的指纹；任一文件被拒绝即停止，之后的文件保持原样。

**宽松列表解析（Beta，默认关闭）。** 有些清单只写 `- 文字` 而不写复选框。用户可对单个来源开启宽松解析：服务端在内存中把 frontmatter 与围栏代码之外、尚非复选框的 `-` / `*` / `+` 列表项视为 `- [ ] 文字` 解析，任务只读显示，文件一个字节不改；开关是本机偏好，随时可关。要让这些任务可写，走同一套接管差异：接管会把这些行真正改写为 `- [ ] 文字 <!--t:ID-->`，用户逐行确认后写入。`GET /snapshot?loose=<以换行分隔的来源路径>` 开启；`POST /sources/adopt/preview` 与 `/sources/adopt` 的请求体接受 `loose: true`。来源对象带 `loose_candidates`（可转换的列表行数）与 `loose`（本次快照是否以宽松方式读取）。

确认请求携带来源路径与预览 `base_hash`；服务端持锁重新读取、比较指纹、生成相同的确定性结果并验证解析，然后记录还原点、原子写回原文件。指纹变化时拒绝确认，要求重新检查差异。客户端提供的 `proposed` 不是写入权威。

## API 与边界

- `GET /api/v1/snapshot`：目录汇总；`?source=docs%2FTODO.md`：单来源视图。
- `POST /api/v1/mutate`：`{source_path, intent}`；intent 中的任务 ID、父 ID、列 ID 都是该文件的原始值。
- `POST /api/v1/sources/adopt/preview`：`{source_path}`。
- `POST /api/v1/sources/adopt`：`{source_path, base_hash}`。
- 历史、扫描与对齐审阅必须选来源；GET 使用 `source` 查询，POST 使用 `source_path`。历史列表及还原点读取检查文件归属，不能把同目录另一个来源的历史恢复到当前文件。

HTTP 根目录在服务启动后固定，不增加任意磁盘目录打开 API，也不提供全局 Capture 收件箱 API；HTTP 随记显示不可用说明，桌面版继续使用个人收件箱，并在分拣时明确选择任务来源。`--read-only` 在服务端禁止 mutation 和接管，不能靠修改前端只读状态绕过。

服务端只接受发现集合中的规范相对来源路径，拒绝绝对路径、`..`、来源内部符号链接及逃离 canonical root 的路径；写入也拒绝符号链接指向的锁或历史目录。显式选定根目录之外的系统路径别名（例如 macOS `/var`）可先 canonicalize，不能因此放开项目内部来源检查。当前实现通过多次检查缩小外部路径替换竞态窗口，不声称具有 `openat` 级无竞态隔离。

## 刷新与兼容

Tauri 递归监听项目目录，包括嵌套来源新建、删除、重命名和忽略规则变更；读取事件不触发反馈循环。Web 端沿用快照轮询，每次按绑定根重新发现。切换根或来源后，旧快照不能覆盖新视图；原生源定向修改与接管携带预期项目根，拒绝旧根的排队请求。

文件内完成策略、说明、Git 物证继续由原单文件核心验证。无 Git 历史时物证明确不可用。源码全仓扫描、历史和对齐审阅仍按选择的来源运行，不把汇总伪装成一个文件。

1. 合并规则 一个视图、一个输入框、两种条目

问题规则
输入怎么分流统一输入条（reading-add 就地改造）：识别出 http(s)/www 链接 → 添加文章（现有 reading_add 管线）；其余文本 → 存入随记（新增 note_append）。识别结果以胶囊提示实时显示在按钮左侧，按钮文案随识别切换。
列表怎么混排阅读列表就是收件箱：文章卡（现状不动）+ 随记卡（新增，同卡片骨架、紫标记替代封面位）。排序 added_at 倒序，混排自然发生；chips 增「文章 / 随记」两个维度（可与状态维度叠加）。
随记怎么编辑点随记卡 → 贴底抽屉（复用窄屏贴底抽屉模式，桌面居中弹层）直编 Markdown 源码；保存即重渲染 content_html。分拣动作（转为任务）保留在随记视图。
随记视图去哪「随记」不再单独占导航项：侧栏导航变「收件箱」（含计数）；随记过滤 = 收件箱 chips 的一维；分拣面板保留——随记视图改造为收件箱的「随记 + 分拣」双列态（见 §6）。

贴底抽屉：拖把手下滑关闭；保存即重渲染、全端可见

抽屉规则
  • 事实源是 markdown 文本域：不做富文本编辑器（移动 WebView 不可靠），工具条只在光标处插语法片段（B / I / 列表 / 任务框 / 分隔线）。
  • 标题从正文派生（首个 # 或首行截断），不单独设标题框——保持随记「轻」的性质。
  • 输入停顿 2s 存本地草稿防 WebView 闪退丢字；显式「保存」才 bump updated_at 上行同步。
  • 「转为任务」：正文 - [ ] 逐条生成 task（走现有分拣管线），随记标 triaged 不删——原话留档。
  • 桌面端同组件居中弹层（max-width 620px，同 project-picker 尺寸语言），交互一致。
  • 冲突保护：保存时若 updated_at 已变 → 提示「他端刚编辑过」，展示双栏 diff 选择保留哪版（LWW 兜底见同步设计稿 §9.3）。

改造点
  • M 数据源：capture_list（inbox.md 文件）→ reading_list(kind='note')（SQLite，随同步）。
  • 0 分拣管线原样：转为任务 → 列选择 → 写入受管 TODO.md，完成语义不变；分拣后随记标 triaged 留档。
  • M 台账右栏（TRIAGE → COLUMNS）从「当前项目列」读到的是同一数据，只是条目来源换了。
  • N 移动端窄屏：分拣列折叠进抽屉底部（capture-item__triage 变一行两钮），delete 保持 icon。
  • M inbox.md 一次性迁移（todo capture migrate dry-run 预览后执行），原文件改名留档；todo CLI 不依赖它（已核实）。

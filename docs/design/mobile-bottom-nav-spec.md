# 移动端底部导航栏规格（自定义 Tab Bar）

日期：2026-11-11
状态：已排期，未实施
来源：2026-11-11 Android 真机验收——侧栏在窄屏重排为底部条后 10 项（9 视图 + 设置）拥挤不可用，用户提出：默认 5 个按钮、最右侧固定个人/设置入口、支持自定义 3~7 个、支持拖动排序。

## 1. 问题

- 现状：`Sidebar.tsx` 的 `navItems`（9 项）在窄屏断点被 CSS 重排到底部，vivo V2425A（2400×1080）上图标 + 文字挤成两行，无优先级、无收纳。
- 「工作空间」「扫描与历史」等长标签加剧换行。

## 2. 目标 / 非目标

**目标**

1. 移动端（窄屏断点内）用专用底部 Tab Bar 取代重排的侧栏；桌面侧栏不变。
2. 默认 5 个按钮：`目标 / 阅读 / 随记 / 总览` 4 个可自定义项 + 最右固定「我的」。
3. 「我的」固定最右：打开现有 SettingsDialog，并在其内提供**未入栏视图的完整入口**（任何视图永远可达，收纳不等于隐藏）。
4. 自定义：栏内可自定义项数量 2~6（加上固定「我的」后总显示 3~7）；超出容量的视图进「我的」。
5. 拖动排序：编辑模式下长按拖拽重排；不用 HTML5 DnD（Android WebView 支持差），用 Pointer Events 自实现。
6. 角标（阅读未读数 / 目标 Doing 数 / 随记数 / AI 数）只在对应视图入栏时显示。

**非目标**

- 桌面侧栏结构不动；不新增视图；不做双栏/抽屉导航；偏好不进本期同步范围（device-local）。

## 3. 数据模型与持久化

- `preferences` JSON 增加一个 device-local 字段（不进 sync-server 范围，与决策③「移动端是副本消费者」一致）：

```json
"mobileTabBar": {
  "order": ["goal", "reading", "capture", "overview"],
  "version": 1
}
```

- 约束：`order` 内 id 必须是合法 `MainView` 且去重；渲染时 clamp 到 2~6 项，非法 id 静默丢弃并回写。
- 未入栏视图不持久化顺序，固定按 `navItems` 原序列在「我的 → 更多视图」。
- 兜底：字段缺失 / 解析失败 = 默认 4 项，**不弹恢复提示**（低价值状态）。

## 4. 交互

### 4.1 常态

- 固定高度 bar（含 safe-area inset），active 态沿用现有选中样式语言（填充块 + accent 色）。
- 「我的」按钮：icon 沿用设置齿轮；打开 SettingsDialog（同时是「更多视图」入口，对话框顶部新增视图分区）。

### 4.2 编辑模式（设置 → 底部导航栏）

- 入口两处：长按 bar 上任意非固定按钮 400ms；或 SettingsDialog 里「底部导航栏」项。
- 编辑 UI：上半区是当前 bar（预览，可拖拽重排、可点「−」移除），下半区是可用视图池（点「＋」加入）；数量 clamp 在 2~6，越界时按钮禁用并给一行说明文案（「至少保留 2 个视图」「最多 6 个视图，其余收纳在『我的』」）。
- 拖拽：Pointer Events（pointerdown 长按起拖 → pointermove 换位（FLIP 动画）→ pointerup 提交）；拖拽中禁用页面滚动。
- 保存时机：操作即写偏好（乐观更新 + 失败回滚），无「保存」按钮。

## 5. 断点与渲染规则

- 沿用现有窄屏断点（sidebar 重排的那一档）；断点内渲染 `MobileTabBar`、隐藏侧栏导航区（品牌区与项目切换器移入顶部或「我的」，实施时按现有顶部空间取舍，不在本规格钉死）。
- 断点外（桌面）不渲染 Tab Bar，行为与现在逐字节一致。
- Android 壳 / PWA / 窄桌面窗口三处断点行为一致（同一套 CSS）。

## 6. 实施切分

| 阶段 | 内容 | 估时 |
| --- | --- | --- |
| M1 | `MobileTabBar` 组件 + 默认 5 项 + 「我的」固定槽 + CSS 替换现有重排 | 0.5 天 |
| M2 | 偏好持久化（`mobileTabBar` 字段 + 读写 + 兜底） | 0.5 天 |
| M3 | 编辑模式（长按入口 + 拖拽排序 + 数量 clamp） | 1 天 |
| M4 | SettingsDialog「更多视图」区 + badge 条件显示 + E2E（mock 路径） | 0.5 天 |

合计约 2.5 天。排期位置：**sync-server（B 层）落地之后**——移动端导航的价值依赖数据通道可用，先通数据再打磨导航。

## 7. 测试与验收

- Rust 侧不动（偏好仍走现有桌面偏好存储，无新命令时）。
- Playwright（mock 传输）：窄视口断言默认 5 项与顺序；编辑模式增删排序后偏好写入；非法持久化数据回退默认。
- 真机验收：V2425A 上 3 / 5 / 7 三种数量截图对比；拖拽在 Android WebView 内不触发页面滚动；「我的」可达全部 9 视图。
- 门禁：`make check-quick` 绿；identity.test.mjs 不受影响（导航文案不在品牌钉死字段内）。

## 8. 未决问题

1. 品牌区与「当前项目」切换器在窄屏的新位置（顶部压缩条 vs 收进「我的」）——M1 实施时定。
2. 「随记」在移动端是否固定必选（它是链接保存需求的核心入口，被移除会让快速保存变深）——倾向给「随记」加默认锁定提示但不强制。

上一版面板的乱点：统计行悬挂分隔符、说明文字悬空、一行 4 个同权重橙色描边按钮、紫色识别胶囊与它解释的主按钮分离、同步按钮（工具）和存入按钮（主操作）抢视觉。下面先立规范基线，再给 4 版完整样式——全部用真实 tokens 渲染，输入框均可交互试玩。

A：识别 = 左缘色条（teal=链接 / 紫=随记）+ 左图标变色 + 主按钮文案；工具全部降为幽灵图标。试试在输入框粘贴一个 https:// 链接

优点
  • 与现有 reading-add 卡片语言完全同构，实现就是现有组件加一行
  • 视觉噪音最低：一个实心按钮 + 三个幽灵图标
  • 识别信息三重内联（色条/图标/文案），不占空间
代价
  • 工具图标需要 tooltip 学习成本（移动端改为收进「⋯」）
  • 「存入随记/添加文章」按钮文案切换是弱信号，赶时间可能注意不到

B：识别结果自动点亮分段（粘贴 https:// 会切到「文章」）；上下文动作随模式切换——文章态显「批量导入」，随记态显「打开文件」

优点
  • 模式显式可见，「一边笔记一边添加文章」两种意图都有确定的家
  • 上下文动作随模式收放，动作数量减半
  • 自动识别 + 手动可改：识别错了用户一键纠正
代价
  • 新增分段控件，比 A 多一层 UI 结构
  • 输入框列宽被分段挤压（窄屏需收为图标段）

C：输入区无边框（仅下划线），与背景融为一体；动作全图标无边框，悬浮才显形——最安静的一版

优点
  • 视觉重量最轻，输入区像页面的一部分而非一个「组件」
  • 头部同步芯片 + 工具图标，一个实心按钮都不多
  • 窄屏几乎不用改
代价
  • 偏离应用现有的卡片语言（reading-add / inline-capture 都是卡片）
  • 无边框输入的可发现性弱，首次使用者可能忽略输入区

优点
  • 分区最明确：一张卡讲完「这是什么、往哪输入、能做什么」
  • 说明文字有了确定的家（卡底 hint 行）
  • 头部洗底与 view-heading 的 accent 元信息色一脉相承
代价
  • 卡片体量最大，列表可视区被压缩
  • 标题进卡片后与全应用其他视图的 view-heading 结构不一致

定稿：方案 A（含 A′ 细节），2026-11-20 用户拍板。已采纳的三个细化：① 识别分流维持前缀口径——http(s):// / www. → 链接文章（需解析、走服务器抓取管线），其余文本 → 随记（免解析直存），两类条目同一输入框并存；② 幽灵工具行图标加 ≤4 字短标签（浏览器保存 / 打开文件 / 批量导入，平行结构）；③ PC 悬停 / 移动端长按（≥500ms）弹出完整功能描述气泡——复用真实代码 data-tip 悬浮模式，移动端用 Pointer Events 计时器挂 tip-open class，不依赖 title 属性。C、D 留档；B 保留为升级路径（若真机试用后觉得识别信号太弱，只换输入条本体，头部/工具行/chips 通用）。

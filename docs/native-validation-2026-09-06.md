## 原生验收发现的缺陷及反证

### 1. Tauri 原生文件拖入处理与 HTML 任务拖放冲突

主窗口原配置使用默认 `dragDropEnabled=true`。原生鼠标拖放复现中，松手后测试文件未发生预期优先级变化；配置回归也在旧配置下失败。

修复主窗口为 `dragDropEnabled=false`，让 WebView 的 HTML 任务拖放处理此交互。`main_webview_uses_html_drag_and_drop` 通过 Tauri 实际配置类型反序列化并检查这一约束。它是配置回归，不单独冒充原生操作验证。

用户随后报告「有时可以、有时不行」，因此没有把单次恢复当成最终通过。

### 2. 文件已写入，界面拒绝合法的重复内容哈希

用户指出从右侧拖回左侧卡片下方空白区必定失败。原生事件记录显示 `drop` 已触发，文件中的子任务优先级已变为 `!1`，而原生可访问性树仍把卡片列在 `!2`。

根因是前端 `staleRevisions` 将曾经见过的内容哈希永久判为过期，且对纯数字外观的哈希按数值比较先后。A→B→A 恢复原内容时会再次产生 A，不能因此拒绝真实写入返回的快照。

反证：真实 `todo serve` 的往返回归在第二次改回初始档位时稳定失败；文件断言先通过，随后界面所在象限断言失败。

修复包括：

- 内容哈希只用于同一项目当前状态的相等判断，不比较大小、不维护历史黑名单。
- watcher 事件作为重新读取当前状态的信号，不直接采用可能迟到的载荷。
- 初次读取、刷新和 watcher 读取共用请求编号与写入边界，拒绝迟到结果及迟到错误。
- 普通任务写入串行；权威写入即使是无内容变化的结果，也会使更早的在途读取失效。

真实服务往返回归随后通过；另增加九项使用真实前端 hook／原生订阅适配器、测试专用 IPC 桩的时序回归。该 IPC 桩不替代真实 Tauri 人工验收。

### 3. 窄窗口子菜单重叠

在 600px 和 680px 下，旧实现可同时打开优先级与「移动到」两个子菜单，固定定位面板互相覆盖。反证测试出现「期望一个子菜单，实际两个」及菜单按钮被遮挡。

修复使用互斥子菜单状态；窄窗口关闭悬停自动展开，子菜单在同一个可滚动面板内排布；动作进入弹窗前先同步卸载菜单。十项菜单交互／焦点回归通过。

## 用户确认的新父子规则

原设计把子任务按自身优先级平铺到不同格子，容易造成「被拆成独立任务」的误解。文件检查和 CLI JSON 均确认当时的子任务仍保留父任务 ID 与缩进，并非父子关系丢失。

用户随后明确选择：

1. 父子始终作为一组展示和拖动。
2. 整组改档统一父任务与全部后代优先级，一次原子写入。
3. 窄窗口单列模式也需要拖动。

据此，象限只将父卡作为拖动和改档入口，后代嵌套展示；旧文件的混合优先级不会因打开视图而被改写。日期筛选保留整组上下文。详细规则见 [象限规格](priority-quadrant-spec.md)。

# CI 并行化耗时复核

## 范围与结论

本文复核三个确切提交的 GitHub Actions `CI` push 运行。三次运行均为 attempt 1，最终状态均为 `completed / success`。`de47901` 的结果已单独核验，不沿用 `c65b6ab` 的绿灯。

同工具链的优化前后样本从 **12 分 45 秒降至 7 分 36 秒**，减少 **5 分 09 秒（40.4%）**。这是一次实际观测，不是并行化的纯因果收益：两次运行的缓存命中、执行主机和网络区域不同，且每个提交只有一个样本。

这三次运行实际使用 Rust 1.88.0 和 Node 22.23.2；本文不能替代 Node 26、Rust 1.98.1 与新版 Actions 组合的 CI 验证。

## 各 job 的实际耗时

| 提交 | Rust／原串行 job | Web 与 Playwright | 真实服务 E2E |
|---|---|---|---|
| c65b6ab | 761 秒，三组门禁串行 | 包含在左列 | 包含在左列 |
| 6ba6104 | 453 秒 | 93 秒 | 193 秒 |
| de47901 | 463 秒 | 86 秒 | 79 秒 |

`6ba6104` 的三个 job 都在 15:34:02 开始；`de47901` 的三个 job 都在 16:25:42 开始。并行化后，Rust job 决定整次运行的关键路径。

优化前后 job 总和只减少 22 秒（2.9%），而端到端减少 309 秒。`de47901` 虽然 job 总和更小，端到端仍比 `6ba6104` 多 10 秒；这不能证明 pnpm 12 更快或更慢。

## 缓存与测量限制

| 项目 | c65b6ab | 6ba6104 | de47901 |
|---|---|---|---|
| Rust 缓存 | 未命中 | Rust 与 Live 均未命中 | Rust 与 Live 均命中同一约 305 MB 缓存 |
| pnpm store | 未命中 | 两个 JS job 均命中 | 两个 JS job 均未命中 |
| Playwright Chromium | 未命中 | 两个 JS job 均命中 | 两个 JS job 均命中 |
| Rust 测试步骤 | 327 秒 | 249 秒 | 245 秒 |
| Clippy 步骤 | 184 秒 | 133 秒 | 142 秒 |
| Live E2E 整个步骤，含构建 | 102 秒 | 131 秒 | 29 秒 |
| Live E2E 测试体 | 10.1 秒 | 11.0 秒 | 11.5 秒 |

三次 CI 使用相同的 Ubuntu 24.04 镜像 `20260831.293.1`、runner 2.337.0、Rust 1.88.0 和 Node 22.23.2，但实际主机及 Azure 区域不同。缓存命中也不意味着不再编译。

`6ba6104` 的 Live job 先保存共享 Rust 缓存，随后 Rust job 的保存日志出现 `Unable to reserve cache ... another job may be creating this cache`。`de47901` 也有 pnpm 缓存保存竞争。相关步骤和 job 最终仍成功；这是非致命缓存竞争，不是 pnpm 安装失败。后续若调整缓存键，应同时比较关键路径与缓存内容，不能只比较是否显示 cache hit。

## 最新 pnpm 12 运行的具体结果

- `de47901` 的两个 `Install pnpm` 步骤均成功，耗时各 4 秒；日志确认安装 `pnpm 12.0.0`。
- 冻结锁文件安装与 esbuild postinstall 成功。
- 交互层测试为 **37 passed、10 skipped**；10 项跳过的是需要真实服务环境的用例，不得记为 47 passed。
- 独立真实服务 job 实际运行这 10 项用例，结果为 **10 passed**。
- `6ba6104` 另有三次成功的 Dependabot Updates 运行，不纳入 CI 耗时样本。

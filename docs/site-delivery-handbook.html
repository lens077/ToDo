静态站三端交付手册

通用模板：把同一份静态站发到 Cloudflare Pages、EdgeOne Pages，以及一个 Kubernetes 集群里的自有域名。按顺序执行；所有项目名、域名、仓库、集群地址都用占位符表示，由使用者提供。不能自动的部分会明确标出。

0 · 前置准备（先做这一节）

不要急着复制后面的命令。先确认这台机器与账号能完成下面这些动作；缺少任何一项，先安装或配置，再继续。带 ASK USER 的项无法从代码推断，必须向使用者提问。

一键预检脚本

#!/usr/bin/env bash
set -u
need=(git gh node npm docker kubectl helm jq curl openssl)
for c in "${need[@]}"; do
  if command -v "$c" >/dev/null 2>&1; then
    printf 'OK   %-8s %s\n' "$c" "$("$c" --version 2>&1 | head -1)"
  else
    printf 'MISS %-8s 请先安装\n' "$c"
  fi
done
command -v edgeone >/dev/null && edgeone whoami || echo 'MISS edgeone：npm i -g --prefix ~/.local edgeone@latest'
command -v glab >/dev/null && glab auth status || echo 'MISS glab（可选）'
docker buildx version || echo 'MISS docker buildx'
kubectl config current-context || echo 'MISS kubectl context'

2 · 目标拓扑

发布源：GitHub 主仓 → GitHub Actions（构建静态站 + amd64 镜像）。

两条静态托管：Cloudflare Pages（海外）、EdgeOne Pages（大陆镜像）。

自有域名：Pangolin → <GATEWAY_VIP>:443 → Cilium Gateway → HTTPRoute → Deployment（nginx-unprivileged:8080）。

GitOps：CI 回写 values 的镜像 tag → GitLab 镜像 → ArgoCD → 集群。

三个端跑同一份 dist/；静态托管只做副本，不接管主域。

3 · Cloudflare API Token：最小权限

CI 需要的是一个 Account API Token，不是本机 wrangler login 的 OAuth token（它通常一小时就过期）。

申请步骤

  1. 登录 Cloudflare Dashboard → 右上角头像 → API Tokens（或 Manage Account → API Tokens）。
  2. Create Token → 最底部 Create Custom Token。
  3. Token name：ci-pages-deploy-<app>。
  4. Permissions 只加一条：Account → Cloudflare Pages → Edit。不要加 Zone、DNS、Workers、R2 权限。
  5. Account Resources：Include → 指定这一个账号，不要选 All accounts。
  6. TTL：按团队轮换周期设置（例如 90 天或 1 年），到期前轮换。
  7. Client IP Address Filtering：如果 GitHub Actions 出口 IP 不固定，留空；能固定出口时再收紧。
  8. Create → 复制 token（只显示一次）。
为什么只给 Pages: Edit：wrangler pages deploy 需要创建 deployment 与上传文件；它不需要读账号设置、也不需要改 DNS。账号 ID 通过 CLOUDFLARE_ACCOUNT_ID 显式传入，因此不必额外给 Account Settings: Read。如果你们的自动化还要列项目或管理自定义域名，再分别补 Pages: Read 或 Zone: DNS: Edit，不要一开始就全给。

验证与写入 Secrets

# 1. token 本身是否有效
curl -s -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  https://api.cloudflare.com/client/v4/user/tokens/verify | jq .success

# 2. 用最小权限实际列一次项目（Edit 包含读）
CLOUDFLARE_ACCOUNT_ID=<account-id> \
  npx --yes wrangler@4 pages project list

# 3. 写进 GitHub Actions Secrets
gh secret set CLOUDFLARE_API_TOKEN
gh secret set CLOUDFLARE_ACCOUNT_ID --body "<account-id>"

轮换时只替换 Secret，不需要改工作流。若 wrangler 报 403，先检查 token 是否绑定了正确账号、是否漏了 Pages: Edit。

4 · GitHub Actions 发布流水线

  1. 触发：main push 或手动 workflow_dispatch；bot 回写提交由 actor 判断挡住。
  2. site job：构建 dist/，发 Cloudflare（有 token 时）与 EdgeOne；把 Pangolin 参数写进 Job Summary 与 artifact。
  3. image job：buildx 构建 linux/amd64 镜像并推送，读回 digest。
  4. gitops job：把 <sha>@sha256:<digest> 写回 values-prod.yaml，提交 [skip ci]，推 GitHub 与 GitLab。
  5. ArgoCD：轮询 GitLab（默认 3 分钟）或手动刷新后同步。

8 · 常见故障

现象原因处理
ArgoCD revision 为空，repo-server 卡在 git fetch集群到 GitHub 不稳定改用 GitLab 镜像，检查仓库 Secret
EdgeOne 自定义域 HTTPS 证书不匹配缺少 _dnsauth 校验 CNAME按控制台提示补记录，等签发
集群内 curl Service 超时CNP 只放行网关身份从网关验收；确需直连再精确放行
ImagePullBackOff拉取凭据缺失或名字不一致检查 imagePullSecret 与 registry 登录
ArgoCD 把手工改动拉回selfHeal 以 Git 为准改 values 提交，不要直接 kubectl edit
EdgeOne 默认域名 401eo_token 只用于预览绑定自定义域名
CI 的 Cloudflare 步骤 403Token 权限不足或账号不匹配只补 Pages: Edit，绑定正确账号

9 · 给执行型 AI 的顺序

  1. 先做 §0 预检，把缺失工具列出来；能装就装，不能判断的值向使用者提问。
  2. 把 §1 变量表填满；任何一项为空都停下。
  3. 确认集群网关、证书 Secret、命名空间与 registry 可访问。
  4. make site-build，确认产物里有目标页面与静态资源。
  5. make k8s-deploy，等 rollout 成功；网关 Host 测试必须 200。
  6. 创建 GitLab 只读 token 与 ArgoCD 仓库 Secret；make argo-apply；Application 必须 Synced/Healthy。
  7. 配置 §4 的 Secrets；手动触发一次工作流，确认三个 job 成功、values 已回写、GitLab 已更新。
  8. 按 §3 的权限说明创建 Cloudflare Token，不要复用本机 OAuth token。
  9. 在 Pangolin 面板按生成参数创建资源；curl https://<MAIN_DOMAIN>/ 验收 200。
  10. 等 EdgeOne 证书签发后再截图或写文档，不要拿共享证书当成功。

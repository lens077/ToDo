Virgo · delivery runbook

官网三端交付手册

给执行型 AI 的作业单：把同一份静态站发到 Cloudflare Pages、EdgeOne Pages 和 k1 集群的 virgo.apikv.com。按顺序执行，每一步都有验收命令；不能自动的部分会明确标出。

0 · 先看结论

端地址发布方式当前状态
海外virgo-overseas.pages.devCI：Wrangler缺 CLOUDFLARE_API_TOKEN
大陆镜像virgo-pages.apikv.comCI：EdgeOne CLI已部署；证书待签发
国内主站virgo.apikv.comArgoCD + Helm集群内 200；缺 Pangolin 资源
不要从 GitHub 直接让 ArgoCD 拉仓库。集群里的 argocd-repo-server clone GitHub 会卡在 git fetch。唯一源是 GitLab 镜像 https://gitlab.com/sumery/virgo.git，GitHub 仍是开发主仓。

2 · 一次性基础设施

下面这些只需要做一次，做完就不再随发布变化。

01 · TCR

镜像仓库

ccr.ccs.tencentyun.com/sumery/virgo-site。首次 docker push 会自动建仓库；本机已 docker login。

02 · GitLab

ArgoCD 只读源

项目 sumery/virgo；Project Access Token 只勾 read_repository，存进 ArgoCD Secret，不进 Git。

03 · Namespace

virgo

由 deploy/argocd/namespace.yaml 创建。AppProject 不放行集群级资源，Application 关闭 CreateNamespace。

04 · EdgeOne

镜像域名

项目 virgo-site，绑定 virgo-pages.apikv.com；DNS 需要站点 CNAME 与 _dnsauth 校验 CNAME。

05 · Pangolin

主域资源

virgo.apikv.com → 站点 k8s-cluster → 10.10.31.240:443 HTTPS，保留 Host，关闭 SSO。

06 · OpenBao

TCR 拉取凭据

路径 k8s/hosting/virgo，属性 tcr-dockerconfigjson。写入权限配好前，chart 用 tcr-pull 兜底。

ArgoCD 仓库凭据（模板在 deploy/argocd/repository.example.yaml）

# GitLab 项目 sumery/virgo → Project Access Token，scope=read_repository
kubectl -n argocd create secret generic repo-gitlab-virgo \
  --from-literal=type=git \
  --from-literal=url=https://gitlab.com/sumery/virgo.git \
  --from-literal=username=oauth2 \
  --from-literal=password=<token> \
  --from-literal=name=gitlab-virgo \
  --from-literal=project=virgo
kubectl -n argocd label secret repo-gitlab-virgo \
  argocd.argoproj.io/secret-type=repository

Pangolin 资源参数

域名:      virgo.apikv.com
站点:      k8s-cluster
Upstream:  10.10.31.240
端口:      443
协议:      HTTPS
Host:      保留原始 Host（不要覆盖）
认证:      公开；关闭 Platform SSO；不加 PIN/密码
EdgeOne 镜像域名: virgo-pages.apikv.com

3 · GitHub Secrets

名字用途状态
TCR_USERNAME / TCR_PASSWORD推送 amd64 镜像已配置
GITLAB_TOKENCI 把 main 镜像到 GitLab（write_repository）已配置
EDGEONE_TOKENEdgeOne Makers 非交互部署已配置
CLOUDFLARE_ACCOUNT_IDPages 账户已配置
CLOUDFLARE_API_TOKENPages 编辑权限缺；工作流会 warning + skip
不要把本机 wrangler login 的 OAuth token 当作 CI token：它的 expiration_time 只有一小时。到 Cloudflare 控制台创建 Pages 编辑权限的 API Token，再 gh secret set CLOUDFLARE_API_TOKEN。

4 · 发布流水线怎么走

  1. 触发：main push 或手动 workflow_dispatch。bot 回写 commit 由 github.actor != 'github-actions[bot]' 挡住。
  2. site job：构建 web/dist，发 Cloudflare（有 token 时）与 EdgeOne；把 Pangolin 参数写进 Job Summary 和 artifact pangolin-resource。
  3. image job：buildx 构建 linux/amd64，推到 virgo-site:<sha>，读回 digest。
  4. gitops job：把 <sha>@sha256:<digest> 写回 values-prod.yaml，提交 [skip ci]，推 GitHub 与 GitLab。
  5. ArgoCD：轮询 GitLab（默认 3 分钟）或刷新后同步到 virgo 命名空间。

5 · Helm chart 的边界

对象说明
ConfigMap非密钥 nginx 配置；监听 8080；/healthz；/screens/ 缓存 7 天
ExternalSecret从 openbao ClusterSecretStore 生成 virgo-tcr（dockerconfigjson）
HTTPRoute挂 default/cilium-gateway 的 https 监听；另有一条 http → https 301
TLSRoute默认 enabled: false。网关已 Terminate TLS；只有新增 passthrough listener 时才开
CiliumNetworkPolicyingress 只允许 ingress / host / remote-node 到 8080；egress 只允许 DNS
PDBminAvailable: 1

6 · Makefile 命令

命令做什么
make site-deployCF + EdgeOne + k8s 三端全发
make pages-deploy只发 Cloudflare Pages
make pages-deploy-eo只发 EdgeOne Pages
make k8s-deploy构建镜像 + 立即 helm upgrade（bootstrap / 回滚）
make argo-apply注册 AppProject / Application；日常发布走 CI + ArgoCD

7 · 验收

# ArgoCD：应为 Synced / Healthy
kubectl -n argocd get app virgo-prod -o wide

# 镜像应为 CI 回写的 digest
kubectl -n virgo get deploy virgo \
  -o jsonpath='{.spec.template.spec.containers[0].image}'

# 从网关进（不要直连 Service：CNP 会拦）
kubectl -n virgo run g --image=curlimages/curl:8.10.1 --restart=Never --command -- \
  curl -s -k -H 'Host: virgo.apikv.com' -o /dev/null -w '%{http_code}\n' https://10.10.31.240/zh/

# 两个 Pages 端
curl -s -o /dev/null -w '%{http_code}\n' https://virgo-overseas.pages.dev/zh/
curl -s -o /dev/null -w '%{http_code}\n' https://virgo-pages.apikv.com/zh/

# Pangolin 资源建好后
curl -s -o /dev/null -w '%{http_code}\n' https://virgo.apikv.com/zh/

8 · 排障表

现象原因处理
ArgoCD revision 为空，repo-server 卡在 git fetch集群到 GitHub 不稳定改用 GitLab 镜像，检查 repo-gitlab-virgo Secret
EdgeOne 自定义域 HTTPS 报证书不匹配_dnsauth 校验 CNAME 缺失或刚加加 _dnsauth.virgo-pages CNAME，等待签发
Pod 里 curl Service 超时CNP 只放行网关身份从 VIP/网关验收，或按需加 fromEndpoints（不要放开全部）
ImagePullBackOffTCR 凭据缺失或 ImagePullSecret 名字不对检查 tcr-pull / virgo-tcr
ArgoCD 把手工 helm 改动拉回selfHeal 以 Git 为准改 values 提交，不要直接 kubectl edit
EdgeOne 默认域名 401eo_token 只用于预览绑定自定义域名

9 · 给 AI 的执行顺序

  1. 确认 kubectl config current-context 是 kubernetes-admin@kubernetes，且能读到 default/cilium-gateway。
  2. make site-build，确认 web/dist/zh/index.html 含 id="free"。
  3. make k8s-deploy，等 rollout status 成功；网关 curl 必须 200。
  4. 创建 GitLab 只读 token 与 repo-gitlab-virgo Secret；make argo-apply；kubectl -n argocd get app virgo-prod 必须 Synced/Healthy。
  5. 配置 GitHub Secrets（见 §3）；gh workflow run deploy.yml --ref main；确认三个 job 通过。
  6. 确认 CI 回写 commit 已到 GitHub 与 GitLab，ArgoCD revision 更新为新的 <sha>。
  7. 在 Pangolin 面板按 §2 参数建资源；用 curl https://virgo.apikv.com/zh/ 验收 200。
  8. EdgeOne：确认 virgo-pages.apikv.com 证书签发完成后再写进文档，不要拿共享证书截图当成功。

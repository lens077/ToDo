D-M0-1 是否把 fix 提交 f5f3ed3 折叠进 C1（重写历史）

选项 A 折叠（rebase/reset，需解禁）｜B 保留修复提交
决定 B：保留 不重写历史。
理由 git reset/rebase 在你的禁令清单里；f5f3ed3 的提交信息已自带解释与折叠方案，历史的诚实痕迹比完美二分更有价值。
锚点 提交 f5f3ed3（crates/todo-core/src/reading.rs）
如何修改 若你想要可二分历史：push 前批准我执行 git rebase -i 77cf6ab^ 把 f5f3ed3 fixup 进 77cf6ab；仅影响未推送的本地提交。

D-M0-2 与 origin/main 合并 + push 的时机

选项 A 本轮合并并 push｜B 推迟到验收后
决定 B：推迟 全程不 push、不合并远端。
理由 push 是对外发布动作，你此前的授权明确要求单独批准；「继续执行直至实现完成」指 M1–M5 的实现，不视为对 push 的解禁。
锚点 本地 main（7 ahead / 1 behind 3613d96，零文件交集）
如何修改 验收时说「push」即可：顺序为 git merge origin/main（预期零冲突）→ make check-quick → git push。

§2M1 · Session–Task 关联闭环 已实现并验证

D-M1-1 关联关系存哪里

选项 A session Markdown 加一节｜B 独立 JSON/SQLite 映射表
决定 A：## Task Links 节，每行一个 - <id>；Markdown 仍是唯一事实源，无 schema 迁移。
理由 会话文件即事实源是既有架构（session.rs:1-8）；加一节保持「文件可手读、Git 可追史」，与现有 extract_section_list 解析器零成本复用。
锚点 session.rs finish()（写入）、parse_summary()（读回）、render_active()（空模板占位）
如何修改 改节名只需同时改这三处 + resume() 的解析；不涉及任何数据库。

D-M1-2 resume 解析任务状态的来源范围

选项 A 仅项目根 TODO.md｜B 走 project.rs 多来源发现
决定 A（v1）：只解析根 TODO.md；找不到的 ID 显示「未在根 TODO.md 找到」，不报错。
理由 resume 必须在任何项目形态下工作（含非 git、无模板）；B 会把 session 模块耦合进 discover 机制（低耦合约束）。多来源项目里其他 Task Source 的任务暂显示未找到——功能可用，只是信息不全。
锚点 session.rs::resolve_linked_tasks()
如何修改 升级到 B 时只改这一个函数（换成 ProjectBackend 发现 + 逐源查找），返回类型不变。

D-M1-3 关联发生的时机

选项 A begin 时声明｜B finish 时记录｜C 两者都允许
决定 B：仅 finish --task <id>（可多次）记录；begin 不带任务。
理由 关联的语义是「本次会话实际做过什么」，事后记录比事前声明准确；避免「声明了没做」的空链接。
锚点 CLI main.rs SessionCommand::Finish 的 --task 参数；Tauri session_finish 经 SessionFinishInput.task_ids（serde default）自动透传，无壳层改动
如何修改 若要 begin 也声明：给 begin() 加可选参数并在 render_active() 预填节内容即可。

D-M1-4 桌面端 UI 形态

选项 A 表单文本框（逗号分隔）+ resume 列表｜B 任务选择器（拖拽/搜索）
决定 A：finish 表单末尾一个「关联任务 ID」输入框（插在第 4 个 input 位，e2e 定位已同步）；resume 卡片渲染 ○ 未完成 · 列 · 正文 / 「未在根 TODO.md 找到」。
理由 Agent 与高级用户以 ID 为工作语言，文本框最直接；选择器需要跨视图状态，收益低。
锚点 ProjectDetailPanel.tsx（finish 表单 + .ws-session__links）、lib/session.ts（mock 任务索引 mockTaskIndex）
如何修改 换选择器只动 ProjectDetailPanel.tsx 一处；mock 索引仅服务 e2e/浏览器演示。

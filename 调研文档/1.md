TODO 漂移（TODO Drift）的深层成因在人机协同开发模式下，TODO 漂移的产生源于三个核心矛盾：第一，上下文窗口衰减与注意力和解。AI Agent 在执行复杂的重构任务或多文件开发时，注意力主要集中在代码语法正确性与功能实现上。随着对话上下文增长，Agent 极易忽略对外部 TODO.md 状态的更新。第二，非确定性变更与超前实现。Agent 在解决某个具体问题时，常会顺带修复相关联的 Bug 或重构周边函数，导致代码库的实际完成度超出了原有的任务定义，而静态看板无法感知这种隐式变更。第三，单向触发机制的局限。传统工具仅支持“人工在 UI 上勾选 -> 修改文件”的单向流动，缺乏“扫描实际代码变更 -> 校验任务状态 -> 反向修正看板”的闭环验证机制。2. 强同步（Strong Synchronization）四重保障体系为了实现任务看板与代码库演进的严格同频，系统设计了分层的强同步保障体系： Agent 行为契约层（AGENTS.md）：在项目根目录维护 AGENTS.md（或 .claude/instructions），将任务更新写入 Agent 的全局操作守则中。强制要求 Claude Code 或 Codex 在领取任务前调用 todo_read 进行 Claim，并在代码写入完成后必须调用 todo_update 归档任务。 协议与工具约束层（MCP / Skills）：基于 Model Context Protocol 暴露标准化 Tool 操作。通过 Zod / JSON Schema 对 Agent 输入进行严格校验，确保写入 Markdown 的格式绝对规范，防止格式损坏。 文件系统与 AST 监视层（notify-rs）：基于 Rust notify crate 对项目下的 TODO.md 和源代码文件进行文件系统级监听。一旦发现物理文件变更，毫秒级触发增量 AST 解析，刷新 SQLite 缓存并通知 UI 界面。 事实校验引擎（Sync Reality Engine）与“同步事实”按钮：提供一键式“同步事实”功能。该引擎不依赖简单的文本匹配，而是通过提取 Git 暂存区与未提交变更（git diff），结合 AST 提取的代码注释（// TODO:），将实际代码状态提交给轻量级 Agent 判定，自动将已完成的代码变更反向同步至 TODO.md。三、 MCP Protocol、Skills 与 Agent 接入规范系统需要同时适配 Claude Desktop、Claude Code CLI、Codex 等多种 Agent 终端，因此采用双传输通道（Stdio & SSE）架构实现 MCP Server。1. 通信通道配置对于 IDE 内置 Agent 或本地 CLI 工具（如 Claude Code），系统提供基于标准输入输出（stdio）的侧车进程（Sidecar）接入方式。对于远程或 Web 端 Agent，系统通过内嵌的 Axum 服务暴露 Server-Sent Events（SSE）通道。2. 四、 技术架构设计与极致性能方案针对用户提出的冷启动必须控制在 2 秒以内、交互无卡顿的严苛性能要求，系统选用了 Tauri v2 (Rust Backend) + SQLite (WAL 模式) + Axum 嵌入式 Server 的高性能技术栈。1. 核心技术选型优势Tauri v2 借助系统原生 WebView（macOS 下的 WKWebView，Windows 下的 WebView2）进行渲染，二进制打包体积仅为 10MB-15MB，运行时内存占用约 50MB，且冷启动时间稳定在 0.3s - 0.8s 之间，完全规避了 Electron 启动慢、内存高的缺陷。SQLite 在开启 WAL（Write-Ahead Logging）模式及内存映射（mmap）后，单机读写性能可达每秒数万次，适合作为 Markdown 文件与前端 UI 之间的高速缓存中介。Axum 作为基于 Tokio 构建的高性能 Rust Web 框架，能够以极低资源消耗运行在 Tauri 进程的后台线程中，完美同时支撑 cURL REST API、Web UI 托管与 MCP SSE 通信。2. 系统组件架构说明系统在架构设计上划分为三大核心层级：前端交互层包含基于 Vite + Solid.js 构建的极轻量级 SPA，同时编译适配 Tauri 桌面端、移动端与纯 Web 浏览器访问。Rust 核心控制层运行在 Tauri 后端进程中，内嵌 Axum Web 服务器处理外围 REST API 与 cURL 请求，内嵌 MCP Server 响应 AI Agent 的 JSON-RPC 调用。文件监视模块（notify-rs）实时捕获物理磁盘变更，并交由增量 Markdown AST 解析器处理。持久化存储层采用“Markdown 为主，SQLite 为辅”的模式。物理 TODO.md 作为提交至 Git 的唯一事实标准，SQLite 仅作为加速图形界面渲染与全文本检索（FTS5）的内存/磁盘索引中介。3. 冷启动与毫秒级渲染优化路径为了保障极致的流畅体验，系统在加载与渲染链条上实施了严格的优化策略：零阻塞异步启动：Tauri 主进程启动时仅加载 SQLite 极简连接池与 UI 壳体。Axum 服务、Git 扫描及 MCP 监听全部推迟至窗口呈现后在独立 Tokio 线程异步初始化。增量 Markdown AST 解析：对比参考 /Users/sumery/lens077/cat 的实现机制，采用 pulldown-cmark 事件流解析器。仅对变动的 Block 进行节点替换，无需全局重解析，确保万行 Markdown 文件的加载与修改响应均在 10ms 以内。UI 增量 DOM 渲染：利用 Solid.js 的细粒度响应性（Fine-grained Reactivity），避开虚拟 DOM 比较开销，修改任务时直接更新对应 DOM 节点，消除 UI 卡顿感。五、 多源导入、代码扫描与通知集成系统不仅满足单个本地文件的读写，还扩展了多仓库 Git 支持、代码注释解析与自动化消息推送能力。1. Markdown AST 解析与双向回写机制系统贯彻“本地 Markdown 为主，看板为辅”的原则：读取与解析：系统使用 Rust 解析 TODO.md，提取复选框语法（如 - [ ] 与 - [x]）、优先级标签（P0-P3）、分配人（@username）及子任务缩进。解析后的 AST 被灌入 SQLite 内存表中以提供 UI 秒级渲染。逆向同步回写：当用户在看板上拖拽任务或勾选完成时，系统通过行号索引与 AST 节点准确定位物理文件位置，精确更新 TODO.md 中的字符串，保留原有文档的元数据与非任务排版格式。2. 多 Git 仓库导入与代码注释扫描为适应复杂项目架构，系统集成了多源任务提取引擎：Git 仓库自动探测：调用 git2-rs 绑定，递归识别 GitHub 或 GitLab 本地克隆项目，定位根目录及子模块下的 TODO.md 或 TASKS.md。代码注释增量匹配：基于 ignore crate（自动尊重 .gitignore 规则）高效遍历源码文件（.rs, .ts, .go, .py 等），通过正则表达式提取包含 // TODO: 或 /* FIXME: */ 的注释行。自动提取的注释任务将被赋予代码位置元数据（如 src/main.rs:42），并同步展示在看板的“代码注释任务”列中。3. REST API 与 cURL 操作支持嵌入式 Axum Web 服务提供标准的 RESTful 接口，极大地方便了开发者使用命令行或自动化脚本进行任务管理。以下为典型接口交互示例：获取当前仓库任务列表：Bashcurl -s http://localhost:3001/api/v1/todos -H "Accept: application/json"

4. 自动化流程与 ntfy 消息通知参考 Monday.com 灵活的 Webhook 与 Automation 触发机制，系统设计了轻量级内置事件总线。当特定事件发生时，通过 HTTP 协议发送 Push Notification：ntfy 原生对接：支持将高优先级任务到期、事实同步纠偏提醒或代码扫描出的严重 FIXME 推送至公共或自建的 ntfy 实例。当触发事实同步发现代码与 TODO 不一致时，系统自动构建 HTTP POST 请求至 ntfy.sh/your_topic，在桌面与移动端同步弹出预警。Webhook 扩展：允许配置自定义 Webhook URL，以便将任务状态变更广播至 Enterprise WeChat、Feishu 或 Slack。六、 商业化变现路径与产品壁垒建设为了确保开源生态与商业利益的平衡，产品采用“Open-Core”（开源核心 + 商业增值）的变现模式，并建立针对个人开发者与企业团队的差异化价值点。1. 商业模式与功能分级下表展示了产品在开源社区版、个人专业版与团队企业版之间的商业化划界：版本划分目标受众许可模式与核心功能商业定价策略Community (社区版)Solo 开发者、开源作者完全开源 (MIT/Apache)。支持本地单仓库 TODO.md 双向回写、基础 MCP/Skills 接入、Tauri 桌面端与基本 cURL API。免费Pro (个人专业版)高级工程师、独立开发者闭源增值插件。支持多 Git 仓库联合看板、代码注释 // TODO: 自动提取、自定义 ntfy 自动化通道、AI 上下文自动填充功能。$6 / 月 或 $59 / 年Team (团队企业版)软件工程团队、企业客户团队授权。支持 Git 原生无冲突协同队列（Git-native Collision-free Queue）、GitLab/GitHub CI/CD 流水线同步插件、企业 SS0 与权限控制。$15 / 席位 / 月 或 私有化部署买断2. 个性化杀手级特性（Feature Moats）为防止竞争对手快速复制，产品必须打造高粘性的差异化功能：第一，AI 上下文自动补全与规格生成（Context Enrichment）。当开发者添加一条简短的 Todo 描述（如 添加 Redis 缓存）时，系统自动调用 Agent 扫描当前代码树，自动为该任务追加推荐修改的文件路径列表、设计注意事项及验收条件（Acceptance Criteria）。第二，人机协同研发效能仪表盘（Velocity Analytics）。基于 Git commit 日志与 TODO.md 历史变更，分析并呈现开发者与 AI Agent 的各自产出占比、TODO 漂移平均纠偏时长等指标，为开发者改善 Agent 提示词与工作流提供数据支撑。第三，Markdown 无缝多视图转换（Multi-View Engine）。不仅支持 Monday.com 样式的标准 Kanban 看板，还支持将 Markdown 任务实时按优先级映射为四象限艾森豪威尔矩阵（Eisenhower Matrix）或甘特图（Gantt View），所有视图的操作均无损回写为标准的 Markdown 标题与列表结构。七、 总结与分阶段落地路线图本调研报告明确指出，随着 AI Coding Agent 的普及，解决代码与任务状态脱节的“强同步”Todo 工具具备极大的市场空白与技术切入价值。基于 Tauri v2 + Rust + SQLite + Axum 的技术路径，能够在保证冷启动小于 1 秒的前提下，同时满足 PC、移动端与 Web 端的操作需求，并通过 MCP 协议和“同步事实”引擎彻底根治 TODO 漂移痛点。项目落地建议分步推进：第一阶段（第 1 -

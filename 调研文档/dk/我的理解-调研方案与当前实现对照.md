## 1. docx 说了什么

《AI时代TODO工具的构建与评测》是一份 AI 生成的「构建方案 + 市场调研」（文末自标「(AI生成)」），六个部分：

1. **技术方案**：MCP 协议 + Skill 规则驱动，Tauri 框架，本地文件系统 MCP Server 读写 `TODO.md`；Rust 引擎扫描代码内 TODO 注释，与 `TODO.md`「自动更新差异」双向实时同步；SQLite 缓存；启动不超过 2 秒。
2. **市场调研**：对比 Todoist、Lark、GitHub Projects、Monday.com、YesDev、Kimi Work 六款工具的 AI 能力、Git 集成与价格。
3. **差异化与商业化**：核心结论「当前市场尚未出现真正解决 TODO 漂移问题的工具」；建议免费版 + 专业版 ¥99/人/月 + 企业版 ¥499/人/月，裂变获客。
4. **路线图**：1–3 个月基础架构与 MCP 集成，3–6 个月 Git 平台扩展与 AI 增强，6 个月后商业化与生态。
5. **风险**：MCP 与 Tauri 兼容性、注释提取准确性、用户接受度、竞品模仿。
6. **结论**：优先实现「强同步」核心功能，快速推向市场。

## 2. 这份 docx 的质量评估

方向与本项目一致（TODO 漂移是真问题、Markdown 为核、Tauri + Rust + SQLite、启动 ≤2s），但细节不可作为依据：

1. **占位符大面积缺失**。多处「如」「使用」「通过」后面的关键名词为空：第 7 行「配置项目根目录为，」、第 12 行「TODO注释（如）」、第 27–28 行「隐藏窗口初始化（）」「使用和标志压缩」、第 34 行「使用实现异步Git操作」、第 135 行「通过库建立」、第 161 行「采用库（Crates.io）」。具体到 crate 名、命令、参数一级，文档基本失去可执行性。
2. **参考文献污染严重**。约 110 条引用中混入大量与主题无关的 arXiv 论文（勒索软件检测 [25][28]、巨噬细胞极化 [73]、微藻脂质培养 [48] 等），另有二十余条纯数字 ID 无法回源。能与正文对上的（rust-mcp-sdk [21]、YesDev 定价页 [91]、todo-to-issue [77]）是少数。
3. **竞品集选错了**。它对比的是个人效率与企业协作工具，完全遗漏真正同赛道的 Backlog.md（6,573★）、Vibe Kanban（27,953★，已关停）、Task Master、beads、Plane——这些恰是 `research/a` 与另一份调研（豆包版）的主角。因此「市场尚未出现同类工具」这个结论方向恰好没错，但它的论证过程不成立：拿错误的对照组得出了正确的判断。
4. **上下文错乱**。如 3.1 节突然出现「AI 自动在 Linear 上更新状态」，与全文其余部分无关，是生成残留。
5. **定价建议与实证相悖**。专业版 ¥99/人/月的订阅制，与 `research/` 的实证结论冲突：中文社区买断心理价位「不超过 ¥100」、Vibe Kanban 用一家公司证伪了团队 seat 费、Things 3 是买断制唯一幸存者（`research/README.md` §7）。表格中 Todoist ¥34/月、Kimi Work 等条目均未核实。

同目录三份材料的质量排序，我的判断是：`research/`（a–g，400+ 来源、一手核查、含「未能核实」清单）＞《AI 时代开发者 TODO 工具：想法评审与市场深度调研》（豆包版，有事实—来源映射表、给出可证伪陈述与 P0 收敛）＞ 本 docx。三份是同一个构想在不同调研深度下的三次回声。

## 3. 当前实现是什么

一句话：docx 所憧憬产品的一个**收敛得多、纪律严得多**的 v1。约 6,700 行 Rust + TypeScript，分三块：

| 模块 | 内容 |
|---|---|
| `crates/todo-core` | 解析（`parse.rs`）、保真回写（`write.rs`）、文件锁（`lock.rs`）、SQLite 投影（`projection.rs`）、对账（`reconcile.rs`）、桌面后端（`desktop.rs`） |
| `crates/todo-cli` | canonical CLI（`init/add/list/done/next/lint/evidence/reconcile/hooks`，`--json` 稳定 envelope + 6 档退出码） |
| `apps/desktop` | Tauri 2 host 直接调用 todo-core（不起 CLI 子进程，见 `docs/adr/0001`）+ React 前端：看板、今日、随记三视图，全局速记窗口 |

支撑它的四层设计文件：`CONTEXT.md`（领域术语：Project Task / Capture / Triage / Evidence / Reconciliation Finding / Today View）、`docs/format-spec-v1.md`（格式规范）、`docs/desktop-mvp-spec.md`（桌面边界与性能预算）、`DECISIONS.md`（存储、开源边界、移动端三大待拍板决策）。

核心机制，按重要度：

1. **`TODO.md` 是唯一事实源**。frontmatter `todo-spec: 1` 做身份标记；列 = `##` 标题；任务 = GFM checkbox 行 + 稳定随机 base36 ID（藏在 `<!--t:xxx-->` HTML 注释里）+ 行尾元数据 token（`#标签 @人 📅截止 ✅完成 !优先级 ^排序 🔗物证 ⛔依赖 →引用`）。未知 token 与人写的一切内容原样保留。
2. **回写是字节区间外科手术**。绝不从 AST 重新序列化（实测 cmark/comrak 都会毁内容）；advisory lock + 乐观锁 + 原子写 + 写后校验；检测到 git 冲突标记就降级只读。SQLite 明确定位为「可随时重建的派生投影」，不是第二事实源。
3. **对账引擎是差异化所在**。Evidence（`🔗sha..sha`）把任务与 commit 范围绑定；对账分结构层（确定性、零误报）与语义层（只吃收窄后的候选集，接口 `SemanticReconciler`，当前实现是 Mock）。spec §6.5 写死了产品安全底线：物证与依赖 token 在任何情况下不可删除、完成状态只升不降、`confirmed` 不等于可自动修、`--apply` 必须报告跳过项。
4. **Agent 接入走 CLI + hooks，不走 MCP**。`todo hooks install` 向 Claude 的 SessionStart 注入任务上下文，向 `CLAUDE.md`/`AGENTS.md` 写入受管指令块（`hooks.rs`）；Codex 无 SessionStart 等价物，仅提供指令块。这是 `research/g-decisions-addendum.md` D1 的落地：「CLI ＞ hooks ＞ MCP」，MCP 留作未来薄壳后门。
5. **个人随记与项目任务分离**。Capture 存全局 `~/.todo/inbox.md`（length-prefixed 格式，防 marker 注入），无完成状态，经显式 Triage 才进入项目仓库——避免临时想法污染 git 历史。

工程质量有独立证据链（`docs/verification-log.md`，实现方 gpt-5.6-sol 与验证方 claude-opus-5 互相制衡、不采信自测）：workspace 70 项测试；契约测试对五类历史 bridge 缺陷做过「注入变红」反证；16 进程并发写零丢失；init TOCTOU 竞态修复前后各 120 轮实测。性能实测：独立二进制冷启动 330–370 ms、`.app` 签名后复核 590 ms（预算 2s）；1,000 任务快照 16.42 ms（预算 100 ms）；投影全量重建中位数 8.99 ms。仓库自身的 `TODO.md` 已由本工具自举管理，带真实 `🔗` 物证。

v1 明确不做（`README.md`、`docs/desktop-mvp-spec.md` §8）：MCP、账号、云同步、团队空间、移动端、REST API、注释扫描、多仓聚合、通知。

## 4. docx 主张与当前实现逐条对照

| # | docx 主张 | 当前实现 | 我的判断 |
|---|---|---|---|
| 1 | MCP + Skill 是架构核心 | 去 MCP，CLI canonical + hooks 保底，MCP 留后门（D1） | 实现正确。MCP 是入场券不是护城河：主流 SaaS 全有官方 MCP（`research/README.md` §1.6），而 Task Master 44 个 MCP 工具吃 21K token 是反例。docx 把接入方式当成了差异化本体 |
| 2 | 代码注释 ↔ `TODO.md` 实时双向同步，「自动更新差异」，甚至监听 `TODO.md` 回写代码注释 | 完全没做，且被规范禁止走向自动改写：对账只报告，完成判定一律 `suspected`，物证不可销毁 | 这是两者最深的分歧。docx 的「强同步」隐含「工具替你改写两边」；实现的立场是「Done is a claim，须对账而非采信」。自动往源代码里写字是信任杀手，误报即死刑（beads 用户禁用 `bd doctor` 的先例）。我站实现这边 |
| 3 | Webhook、多仓管理、CRUD API、ntfy 通知，1–3 个月全上 | 全部列入 non-goals，分阶段后置 | 实现正确。范围蔓延是 `research/` 点名的死因之一；docx 的路线图没有排优先级的证据基础 |
| 4 | SQLite「缓存」 | SQLite = 纯投影，可重建，绝不反向写文件（验证日志 T2 专项审查） | docx 没有回答「权威归属」这个最关键的问题——缓存与事实源的边界不写死，就会重演 cat 项目「SQLite 变事实源」的方向错误 |
| 5 | 启动 ≤2s，手段是隐藏窗口、压缩二进制、MessagePack 替代 JSON | 实测 0.33–0.59 s，靠架构纪律（本地权威数据 + 投影首屏）而非传输格式技巧 | 目标一致且已超额达成。`research/` 的洞察更根本：快慢的决定变量是「权威数据在本地还是云端」，Linear 用 Electron 也快 |
| 6 | 免费版 + ¥99/人/月 + ¥499/人/月 订阅 | 未定稿；`DECISIONS.md` ② 给出三层结构（格式开放 / 内核 MIT 或 fair-code / 对账引擎闭源收费），倾向买断或 Obsidian 模型 | docx 的订阅定价与社区实证相悖；「对账引擎是付费点」这一层 docx 完全没有识别出来 |
| 7 | 「看板仅为编辑入口，修改后同步回写 TODO.md」 | 已实现：拖放发 intent，Rust 回写成功返回新 Snapshot 后界面才确认 | 这是 docx 与实现真正对齐的核心点，也是整个构想里最稳定的共识 |
| 8 | 「同步事实」按钮让 AI 查询代码实际状态 | 升级为常态机制：Evidence + `todo reconcile` + hooks 自动注入上下文；按钮只是入口之一 | 实现更彻底。「按钮 = 用户要记得点」是原痛点的翻版（`research/README.md` 结论 4） |

## 5. 我的综合理解

1. **三份调研是同一构想的三个成熟度**，真正驱动实现的是 `research/` + `DECISIONS.md`。docx 的价值是提供了一个独立视角的交叉验证：它在不知道 Backlog.md 存在的情况下，也得出了「TODO 漂移无人解决、Markdown 为核、Tauri 高性能」的相同方向——说明这个方向对不同调研路径是稳健的。
2. **整个项目最重要的一次概念跃迁，是从「强同步」到「对账」**。docx（以及最初构想 R4）说的是同步：让工具自动把两边改成一致。实现说的是对账：代码改动只是物证，完成是一个待核实的声明；结构层零误报自动查，语义层 AI 提议、人确认，证据永不销毁。这个跃迁把产品从「又一个会误报的自动化工具」变成「可以被信任的审计层」，是付费理由的来源，也是 docx 完全没有触及的层次。
3. **护城河的判断分歧**：docx 认为差异化在 MCP 深度集成；`research/` 逐条核查后证明「同步事实/对账」才是全类目真空（`research/README.md` 结论 3），MCP 只是接入方式且已非最优。当前实现把对账引擎放进 core 并用规范级约束保护它，与 `DECISIONS.md` ②「对账引擎留在商业层」呼应。我认同这条线。
4. **docx 的剩余价值**是一份「别忘了这些面」的检查单：中国市场竞品视角（Lark、YesDev、滴答生态）、注释扫描需求、MCP 调用成本预算意识、获客渠道想法。每一项在 `research/` 里都有更扎实的版本（注释扫描必须先解决分诊与去重，见 R5 裁决），采纳时应以后者为准。
5. **当前实现相对愿景的缺口**（与 `TODO.md` 待办对齐）：语义对账只有 `MockSemanticReconciler`，「AI 提议 + 人确认」的闭环还没接真模型，也没有桌面确认 UI；Codex 侧无 SessionStart 等价注入；桌面端 Playwright 回归未进 CI；无 release 分发；注释扫描、多仓、通知、移动端全部在后。换句话说，「对账代替自觉」的故事已经有了骨架和安全底线，但「AI 提议」这半边还是空的——这是下一步最值得投入的位置。
6. **对这份 docx 的处置建议**：归档为「外部意见・低置信」。它与 `docs/format-spec-v1.md` §6.5 存在方向性冲突（自动更新差异 vs 证据不可销毁、状态只升不降），如果未来被当作事实源引用，最可能造成的破坏恰好落在产品最核心的安全线上。引用其中任何数字前需逐条核实。

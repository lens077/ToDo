## 二、终审统一标尺(先立规矩,再断案)

三场对抗的严重度分歧,几乎全部源于标尺不一(gpt-2 用「是否阻断快速开始」、claude-3 用「伤害机制分层」、gpt-3 用「影响上限」)。终审统一采用**伤害机制标尺**,理由:本产品的存在理由就是消灭「错误的事实感」,其自身哲学(spec §6.5)即以「不可见的伤害最危险」为第一原则——终审标尺应与被审产品的价值观同构:

- **高**:README 的陈述会制造**不可见的错误信任**(假绿、静默数据改写/覆盖、凭据暴露)——失败不自我宣告,用户带着错误认知继续前进;
- **中**:陈述确定性为假或制造显著错误预期,但失败**响亮、可自诊断**,不产生持续错误信任;
- **低**:局部接口口径错误,存在其他自纠路径,影响面小。

修复优先级是另一维度(修复成本、暴露频率),与严重度分开标注。对抗3中 claude-3 撤回「一句话可修所以降级」论据(修复成本非严重度参数)——终审确认该撤回,并双向适用:低成本既不降也不升严重度。

## 三、跨场归一裁决(五个分歧点,captain 裁定)

### 裁决 1:MSRV(A4/B1/C3)——成立,**中**,修复优先级 P0

三场终局分别为 中/高/中;captain 质询后 gpt-1 自我改判为高(理由:环境表是二元契约,对照表行动的读者 100% 失败,流行度只应影响修复排序)。
**终审裁定:中。** 依据统一标尺:1.74–1.84 区间构建失败**响亮且自诊断**(cargo 直接点名所需版本,claude-2 真装 1.74 实测三连 exit 101、27 个锁定包 edition 2024 在 manifest 解析即死)——无假绿、无数据损害、无持续错误信任。gpt-1/gpt-2 的「高」基于「契约虚假度」维度,记录在案且尊重其自洽性;两标尺下**修法完全一致**:`README.md:15` 改为锁定图实际值(CLI ≥1.85、整仓 ≥1.88)或收依赖并以 `cargo +1.74 build --locked` CI 门禁证明。改一个数字的事,立即做(P0)。附注:README 所在提交自称「verified build and run commands」,而 MSRV 恰不在被验证之列——这是「未验证的声明不要写成已验证」的教科书案例。

### 裁决 2:hooks 密钥回显警告错位(A6/B7/C7)——成立,**高**(裁决三场唯一贯穿分歧)

三场终局:A6=高、B7=中、C7=高/中留档(全系列唯一坚持到底的分歧)。gpt-3 终审答复给出了完整的钢人与可改判条件;claude-2/claude-3 的「中」基于期望伤害加权(双重概率折扣)。
**终审裁定:高。** 理由:①资产等级——凭据是全案最高价值资产,且泄露发生时**不自我宣告**(受害者不知道已泄露),恰属标尺「高」的机制定义;②README:75 是全文**唯一的安全警告**,其精确主语(`preview`)对并列展示的三个同面命令构成**主动的反向暗示**——这是 README 自己书写的增量伤害,非单纯实现层缺陷;③secret 前提由 README:75 自认,非臆测;④stdout 是否持久化常由外围环境(CI 日志、终端录制、provisioning)自动决定,不需要用户第二次主动行为;⑤本产品自身的安全哲学(§6.5「证据不可销毁」全节)从不接受概率论证稀释安全线,终审同构适用。期望伤害派的论据(preview 是最大分享通道、警告已种下意识)如实留档;若未来证实 settings 契约不落原始 secret,可复议降中(gpt-3 列明的改判条件,终审采纳为复议门槛)。
修法(双方本无分歧):README:75 警告范围扩至 `preview/install/uninstall`(含 `--json`);实现层默认摘要+脱敏、完整内容走 `--show-content`(入 backlog)。

### 裁决 3:B4「完成状态权限」——**移出 README 缺陷清单**,转产品治理缺口

captain 质询指出层级错位:README:7「只报告,不擅自改写完成状态」主语是引擎,陈述为真;「完成状态须人确认」只存在于调研建议(research/README.md §5 R4)与理解文档的叙事口径,**不存在于本仓库任何规范性文件**(spec §6.5.4 只约束引擎;CONTEXT.md 只约束 Finding;DECISIONS/ADR 未拍板)。gpt-2 复核后正面接受:「B4 应从 README 缺陷撤下,README 没有义务替未拍板模型作承诺」。
**终审裁定:B4 撤出 README 缺陷清单。** 真实发现改记为:**hooks 受管指令块(`evidence → todo done`)与调研建议 R4(agent 完成后进 InReview)之间存在未拍板的治理分歧**——应补一份 ADR 拍板「谁可写完成状态」:若采「done 是 claim、事后对账审计」模型(现状可如此解释),ADR 写明即可;若采 R4,则 hooks 指令块需改。README 可选加 gpt-2 的中性披露句:「`todo done` 记录操作者(人或 agent)的完成声明;Evidence 只证明关联改动存在,`reconcile` 只报告异常,不把该声明当作验收结论,也不自动改写状态。」

### 裁决 4:SQLite 投影呈现(B8/C12)——**非缺陷**,可选澄清

claude-2 以 gpt-2 自设口径否决 B8,gpt-2 接受;captain 质询后 gpt-2 裁定 C12 同死,gpt-3 终审答复正面接受撤回 C12(「三处字面陈述都为真,推断不足以达到错误操作门槛」)。
**终审裁定:双撤确认,非缺陷。** README:6「SQLite 只是派生投影」是收缩边界声明,修辞方向与夸大集成相反。可选编辑(非必修):第 6 行后补「当前 CLI 与桌面直接解析 Markdown,投影未接入执行路径,接入触发条件见验证日志」。

### 裁决 5:C2「skipped 0」双关加重情节——确认,C2 定格为**全案第一重发现**

终审人亲自核验:human 输出的「applied 0, skipped 0」中 `skipped` 指「跳过的手工修复项计数」(`skipped_manual`),与 `report.skipped`(git 检查被跳过的原因列表)**同词异义**。shallow clone(CI 常态)下用户屏幕同时出现「no reconciliation findings」与「skipped 0」,而 git 物证检查恰恰整层被跳过——不是沉默,是**肯定性矛盾**。该证据由 claude-3 首轮补出、gpt-3 采纳(归属如实记录);gpt-3 终审答复进一步指出修复顺序:先修 human schema 术语分名(`checks_skipped` vs `findings_requiring_manual_action`),再改 README。`--json` 出口含真实 `report.skipped`,机器消费者不受骗——沉默精确限定于 human/退出码/hooks 三出口。

# 价值与商业化总纲

> 来源：`调研文档/1.md`〔1〕、`调研文档/AI 时代开发者 TODO 工具：想法评审与市场深度调研.md`〔2〕、`调研文档/AI时代TODO工具的构建与评测.docx`〔3〕、`调研文档/功能整合总表.md`。
> 证据底稿：`research/`〔R〕、`research/g-decisions-addendum.md` 与 `DECISIONS.md`〔D〕、`docs/verification-log.md`〔V〕。
> 撰写日期：2026-09-01。回退点：commit `728f9f3`。
> 本文不替换 `README.md` 与 `TODO.md`，也不是规范文件。功能口径以 `docs/format-spec-v1.md` 为准。
> 与 `功能整合总表.md` 的分工：那份是 109 条的清单与状态台账；本文只回答三个问题——什么最值钱、什么能收钱、先做什么。

## 1. 一页结论

**定位**：给 AI 协作开发者的任务对账器。todo 永远在你的仓库里，永远和代码对得上。

**最值钱的三件事**（按价值降序，理由见 §3）：

1. **对账引擎 + Git 物证绑定**——全类目真空，逐条核查过 Backlog.md、Task Master、beads、Shrimp、ccpm 的命令面与源码，无一实现「扫代码反向校正任务」〔R〕。
2. **无损回写工程**——生死线，且淘汰过前人。Obsidian Kanban 因全文件重序列化毁数据弃坑，同生态的 Obsidian Tasks 用行级改写活到 413 万下载〔R〕。
3. **对账安全底线**（`docs/format-spec-v1.md` §6.5）——决定信任，而信任崩塌一次就不会再开启对账。

**最能收钱的三件事**（理由见 §5）：

1. 托管 AI（语义对账、注释分诊、随记分拣）——有边际成本，进订阅。
2. 多仓聚合 + 回顾视图（周/月/年、热力图、周报）——零边际成本，进买断。
3. 跨设备同步中继 + 移动推送——本地优先自己做不到的事，进订阅。

**最该砍的三件事**：

1. **看板作为主卖点**——三份文档都把它当核心，〔R〕判定它是构想中最弱的一环。Vibe Kanban 27,953★ 仍找不到商业模式并关停。
2. **MCP 作为差异化**——主流 SaaS 全部已有官方 MCP，它是入场券不是护城河。
3. **让 agent 自动写完成状态**——这是漂移的成因，不是解法。

**当前最大缺口**：语义对账仍是 `SemanticReconciler` trait 加 Mock。差异化叙事的一半没有兑现。

## 2. 价值评估方法

三份文档都在列功能，没有一份说明「凭什么认为这条值钱」。本文用四条判据排序，每条都可证伪：

| 判据 | 含义 | 不满足的后果 |
|---|---|---|
| **J1 真空度** | 竞品是否已经做到 | 做了也拉不开差距 |
| **J2 复刻成本** | 竞品照抄需要多久 | 窗口期内被抹平 |
| **J3 信任权重** | 出错是否不可逆 | 决定能否收费，也决定能否被信任 |
| **J4 边际成本** | 每多一个用户是否增加成本 | 决定收费形态：零成本进买断，有成本进订阅〔R〕c §13 |

J1–J3 决定**要不要做**与**做的顺序**；J4 只决定**怎么收费**，不参与价值排序。

## 3. 最有价值的能力

### V1 对账引擎 + Git 物证绑定

| 判据 | 评分 | 依据 |
|---|---|---|
| J1 真空度 | 高 | 逐条核查五个同赛道工具的命令面与源码，无一实现；只有零散 CLI/技能级先例〔R〕a §9.3、f §2 |
| J2 复刻成本 | 中高 | 机制不难想，难在与无损回写、安全底线绑在一起才成立 |
| J3 信任权重 | 最高 | 误报即死刑：beads 用户「I've banned my agents from running `bd doctor`, because it reports false positives」〔R〕 |

**为什么是它而不是别的**：痛点被强验证且比构想描述的更严重——实测 27% 幽灵任务（代码已完成、状态未更新），Claude Code 官方 issue #39961 实测 50–75% 的会话浪费在重做已完成的工作〔R〕e §1。这不是体验问题，是成本问题（烧 token）和正确性问题（改坏代码）。

**降本增信的关键设计**：`🔗sha..sha` 把任务绑定到 commit 范围，对账从「让 agent 重新理解代码」降级为「比对物证与 HEAD」，可信度与成本好一个量级。**三份来源文档都想做对账，但没有一份回答「对账拿什么当依据」**——这是它们共同的空缺。

**现状**：结构层（零误报）与 Git 物证层已交付；语义层只有 trait 与 Mock。

**已知偏差**：shallow clone 或非 git 环境下物证检查整层跳过，而 human 输出、退出码、hooks 三个出口仍显示无异常（对抗终审 F1，全案第一重发现）。**这条必须先修**——一个在 CI 常态下静默失效的对账引擎，比没有对账更危险。

### V2 无损回写工程

| 判据 | 评分 | 依据 |
|---|---|---|
| J1 真空度 | 中 | 有人做到过（Obsidian Tasks），但在「看板 + 仓库文件」这个组合里没有 |
| J2 复刻成本 | 高 | 同生态对照实验证明它淘汰过前人 |
| J3 信任权重 | 最高 | 毁一次数据就结束 |

〔2〕自己把它标为「最大不确定性」与「生死线」，且指出这是大部分同类项目回避它的原因。**这一条已经被解决**：字节区间外科手术、未触碰行逐字节不变、写后校验、16 进程并发写零丢失〔V〕。

**这是目前唯一一条「竞品想抄要花几个月」的能力**。三份文档里〔1〕称其为「毫秒级双向实时 AST 解析与回写」——口径是错的，从 AST 重序列化恰是毁数据的那条路。

### V3 对账安全底线（§6.5）

不是功能，是一组不可协商约束：证据不可销毁、完成状态只升不降、完成判定一律 `suspected`、`--apply` 必须报告跳过项。

**为什么单列为价值项**：它是 V1 能被信任的前提。`🔗` 指向的 commit 被 revert，含义是「你以为做完的工作被撤销了」——这是用户最需要看到的诊断信号，删除它等于发现火灾后把火警拆掉。

三份文档全部没有触及这一层。〔1〕〔3〕的设计反而会破坏它（见 §7.1 冲突 2）。

### V4 CLI canonical + hooks 自动注入

| 判据 | 评分 | 依据 |
|---|---|---|
| J1 真空度 | 中 | Backlog.md 已走同路线并明写「MCP is a legacy, optional adapter, the CLI is canonical」 |
| J2 复刻成本 | 低 | 接入方式本身易复刻 |
| J3 信任权重 | 中 | 决定 agent 会不会真的用 |

价值不在「CLI」，在 **SessionStart 主动注入**：三份文档的接入方案都依赖 agent 记得调用工具，而「agent 无视任务系统」正是〔R〕e §N10 记录的失败模式。会话开始时主动推送任务快照与对账摘要，是把「靠自觉」换成「靠机制」。

〔R〕的判断很直接：「按钮 = 用户要记得点 = 原痛点的翻版」。三份文档设计的都是按钮。

### V5 本地事实源与数据主权

叙事价值高于功能价值。可用的现成论据：Height 关停后删除用户数据、Vibe Kanban 云端看板随公司失效、Pocket 2025-07-08 关停——**厂商死了数据还在**是可以反复讲的故事。

配套硬事实：Todoist 云同步架构迫使它设「每项目 300 任务」硬上限，本地 SQLite 无此限制，可直接当宣传点〔R〕c。

### V6 语义对账（AI 提议 + 人确认）

**当前唯一未兑现的高价值项**。〔R〕c §3、§12.2 记录了反面先例：Height 2.0（autonomous project management）从全量发布到宣布关停仅 5 个月；Microsoft Planner Agent 回撤到默认 draft 待批准。「AI 提议 + 人确认」是行业已验证的正确姿态，也是差异化叙事的另一半。

三条红线（〔D〕D5）：提议 + diff 预览 + 人确认，绝不静默重排；结构性识别零误报打底，LLM 只做语义增强且可关；说清边界，两文件以内的小改动不值得走 AI 流程。

### V7 中文默认

真空位：Backlog.md 的 i18n PR 被关闭，全类目英文。中文社区诉求明确（本地数据、买断、微信生态），且存在「本地数据 + 跨平台 + 不订阅 = 不可能三角」的明确未满足需求〔R〕e §5。

### V8 随记（Capture）作为高频入口

结构正确：高频入口（每天 N 次）带动低频资产（看板每天 1–2 次）。中文市场先例 flomo 验证了「快速记录 + 回顾」的付费意愿〔D〕D6。

三份文档一条都没提到这个入口。

## 5. 商业化

### 5.1 划线原则

免费层做**规模阉割**（单仓库）而非功能阉割。核心闭环必须免费可用，否则用户体验不到价值，转化无从谈起——imdone 用 12 年换来的教训是 time-to-first-value 决定生死（npm 月下载约 2 千，$18→$9 降价后 24 小时内只拿到 2 个付费用户，作者复盘「Price is rarely the final boss」）。

付费按**边际成本**拆两档：零边际成本的功能进买断，有边际成本的服务进订阅。

### 5.2 三档划分

| 免费（单仓完整可用，永不强制登录） | 买断（一次付费 + 12 个月更新窗） | 订阅（有边际成本） |
|---|---|---|
| 看板 + 今日视图 + 随记速记（手动分拣） | 周/月/年回顾、热力图、周报卡片 | **托管 AI**：语义对账、注释分诊、随记分拣，含额度 |
| CLI / hooks 全量、`--json`（agent 生态信任基石） | **多仓聚合视图**、「我有 15 分钟该做什么」 | 跨设备同步中继 |
| 对账结构层（零误报）+ 语义层 **BYOK** | 高级看板：泳道、WIP 上限、依赖图 | 托管推送（移动端 APNs/FCM 通道） |
| 单仓库、系统本地通知 | ntfy / Bark 推送（用户自己的 topic，零边际成本） | 团队空间（远期，谨慎立项） |
| Obsidian / VS Code 插件本体 | JetBrains 插件（走其原生付费市场） | 企业私有化部署支持（按合同） |

三个要点：

1. **BYOK 免费是刻意的**。开发者自带 API key 可跑全部 AI 功能；托管档卖的是零配置、批量价、移动端可用。不允许 BYOK 会被喷「圈钱」。
2. **ntfy / Bark 放买断档**，因为通道是用户自己的，我们零成本。
3. **免费层永远不登录完整可用**，登录只在购买或同步时出现。

### 5.3 定价

〔R〕§7 的推荐：一次性买断 + 12 个月更新窗（到期软件永久可用），国内 ¥98–148、国际 $29–39，续更 6 折。可照抄的成熟范式是 Sublime（一次性 + 3 年更新 + 一个 key 通用所有设备）与 JetBrains（订阅满 12 个月得永久 fallback 授权）。

**不做订阅**（除非提供真实服务端价值），**不做 lifetime deal 促销**。定价模式一开始就要选对——Kaleidoscope 买断转订阅引发的是「背叛」叙事，开发者用户当场迁移。

### 5.4 三份文档的定价建议对照

三份文档给了三套互不相同的价格，且都与实证冲突。

| 来源 | 建议 | 与实证的冲突 |
|---|---|---|
| 〔1〕 | Community 免费；Pro $6/月 或 $59/年；Team $15/席位/月 | 团队 seat 费已被 Vibe Kanban 用一家公司证伪；订阅制对本地优先工具阻力大 |
| 〔3〕 | 免费版含每月 10 次 MCP 调用；专业版 ¥99/人/月（年付 ¥999/人）；企业版 ¥499/人/月（年付 ¥4999/人） | 与中文社区买断心理价「不超过 ¥100」相差一个量级；「免费版限 MCP 调用次数」在 v1 无 MCP 的前提下不成立 |
| 〔2〕 | 开源核心 + 付费增值（云同步/多端、团队协作、AI 校验额度与周漂移报告、企业私有化） | 方向与〔D〕§5.3 一致，未给数字，可直接采纳其方向 |
| 〔R〕§7 | 买断 ¥98–148 / $29–39 + 12 个月更新窗，或 Obsidian 模型 | — |

参照坐标：Things 3 是买断制唯一幸存者（三平台合计 $64.97）；滴答清单国内 ¥139/年 vs 国际 $49.99/年，说明区域定价是必修课；monday.com FY2025 营业总收入约 12.32 亿美元〔2〕F1，验证的是 B2B 订阅意愿，不是个人开发者工具的。

### 5.5 三条铁律

1. **不登录也能完整使用本地功能。** HTTP API、ntfy、云同步、商业化全部必须是可选增量。Vibe Kanban 2026-02 强制登录上云（issue #2687，33 👍），社区当场决裂，两个月后关停。
2. **不指望团队席位费。**
3. **格式开放与代码闭源可以并存。** 格式 spec、lint、解析库开源换 agent 生态信任；对账引擎与 GUI 留在商业层。beorg 与 Obsidian 都是「闭源产品 + 开放格式」的成功样本。

### 5.6 未评审的营销建议

〔3〕提出裂变邀请解锁、ChatGPT 生成 Reddit/Product Hunt 文案 + Buffer 定时发布、获客成本控制在 $1 以下、申请专利保护核心技术。这些均未经评审，且与〔R〕§8 的增长建议（Obsidian Kanban 弃坑留下的约 261 万下载存量用户、cat 桌宠联动、每日站会卡片）不在同一证据等级上。

**专利一项不建议采纳**：护城河在无损回写工程与对账安全底线，不在可专利的机制。

### 6.3 与已交付实现重复的条目

三份文档提出、仓库已经做完的 13 条：`TODO.md` 事实源、SQLite、看板拖拽回写、无损 round-trip、外部编辑刷新、冷启动性能、交互延迟、对账（结构层与物证层）、Agent 行为契约、桌面看板视图、中文默认、非目标声明、文件监听。

**整合规则**：这些不再作为新需求进入待办，只在 §7 记录口径差异。

## 7. 冲突功能表

### 7.1 三份文档与仓库决策的冲突

以下六项不能靠整合调和，须择一。

| # | 议题 | 三份文档 | 本方案 | 依据 |
|---|---|---|---|---|
| 1 | MCP 是否 v1 核心 | 三份一致认为是 | 去 MCP；CLI canonical + hooks；`--json` 面即未来薄壳 schema | 〔D〕D1；主流 SaaS 全有官方 MCP |
| 2 | **谁有权写完成状态** | 〔1〕要求 agent 完成后「必须调用 `todo_update` 标记 done」；〔3〕「自动更新差异」 | 对账只报告；完成判定一律 `suspected`；状态只升不降；物证不可删除 | `format-spec-v1.md` §6.5；「Done is a claim that must be reconciled」 |
| 3 | 是否回写源代码注释 | 〔3〕主张监听 `TODO.md` 后回写代码注释 | 不做 | 与「工具只修改自己认识的行」冲突 |
| 4 | 定价模型 | 订阅制，三套价格 | 买断 + 12 个月更新窗，或 Obsidian 模型 | §5.3、§5.4 |
| 5 | 前端框架 | 〔1〕Solid.js | React | 快慢的决定变量是权威数据在本地还是云端，不是框架；Linear 用 Electron 同样零延迟 |
| 6 | 阶段顺序 | 〔1〕第 9–12 周上 REST + 多源 + 通知 | 排在既定顺序第 6 位之后 | 〔D〕§6、§7.5 |

**冲突 2 是全表最重要的一条。** 三份文档设计的机制（让 agent 自动写完成状态）恰是漂移的成因：实测 27% 幽灵任务，「creates 可靠、completes 有损」。采纳它等于用引发问题的机制去解决问题。

冲突 8 说明一件事：**三份文档「市场无雷同产品」的结论一致，但没有一份查到了真正的竞品**。结论碰巧正确，论证过程都不成立。

## 8. 优先级划分

排序原则：**先修可信度，再补差异化，最后扩面**。理由是 V1 的价值完全依赖「对账说没问题时，真的没问题」；在 F1/F3 修复前扩功能面，等于在漏水的地基上加层。

### P0 · 可信度修复（阻塞一切）

| 项 | 内容 | 为什么是 P0 |
|---|---|---|
| P0-1 | 修 F1：shallow/非 git 下物证检查跳过仍显绿；`skipped` 术语分名 | 对账在 CI 常态下静默失效，比没有对账更危险 |
| P0-2 | 修 F3：乐观锁接线，退出码 5 生效 | README 已声明的能力实际不存在 |
| P0-3 | 修 F2：`--adopt` 排除代码围栏 | 违反自家 spec §1.3，会污染用户文件 |
| P0-4 | 修 F4：hooks 密钥警告范围扩至 `install`/`uninstall` | 凭据是最高价值资产，且泄露不自我宣告 |
| P0-5 | 修 F6：MSRV 数字改对 | 改一个数字，当前对照 README 行动的读者 100% 构建失败 |

**出口条件**：五项全绿，且新增回归测试。

### P1 · 差异化补完（决定产品是否成立）

| 项 | 内容 | 价值来源 | 依赖 |
|---|---|---|---|
| P1-1 | **语义对账接真模型（BYOK）** | V6，差异化叙事的另一半 | P0 |
| P1-2 | 桌面端 Finding 确认 UI | V6 的必要配套，「AI 提议 + 人确认」缺一不可 | P1-1 |
| P1-3 | 修 F10（lint 查重复 ID）、F5（`--no-semantic` 标注） | 契约一致性 | — |
| P1-4 | Playwright 回归进 CI、三项人工验收、release 构建与分发 | 没有分发就没有用户，没有用户就没有证据门 | — |
| P1-5 | **在真实项目 dogfood 2 周，建立基线** | 〔2〕的验证计划：round-trip 后 git diff 为空的比例、启动与交互耗时 | P1-1、P1-4 |

**出口条件**（〔2〕给的证据门，本文采纳）：round-trip 无损率达到可接受阈值〔阈值待确认，须先建基线〕；5 名外部开发者试用后，观察漂移报告是否让看板重新被信任。

**停止条件**：round-trip 无损率显著低于阈值，或竞品在窗口期内已覆盖核心体验。

## 9. 不做清单

| 不做 | 理由 |
|---|---|
| 让 agent 自动写完成状态 | 漂移的成因，不是解法 |
| 引擎自动纠偏 / 自动更新差异 | 误报即死刑；`--apply` 只做一种确定修复 |
| 回写源代码注释 | 与「只修改自己认识的行」冲突 |
| 定期轮询（每分钟扫 Git） | 与 watcher + hooks 重复，引入常驻开销 |
| MessagePack 替代 JSON | IPC 不是瓶颈；`--json` 是对外契约 |
| Node.js 常驻 MCP Server | 与「本地、快、单进程」定位冲突 |
| 团队席位费 | 已被证伪 |
| 申请专利 | 护城河不在可专利的机制 |
| 强制登录 | 铁律，见 §5.5 |
| 通用个人待办、日历排程、非开发者市场 | 〔2〕的 non-goal，本文沿用 |
